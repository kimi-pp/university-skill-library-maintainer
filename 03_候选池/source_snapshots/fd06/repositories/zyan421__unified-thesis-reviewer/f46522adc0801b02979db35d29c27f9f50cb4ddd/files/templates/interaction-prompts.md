# 交互话术模板（v2.0.0，5 个节点）

本文件定义主工作流的 5 个用户交互节点话术。**v2 相对 v1 的变化**：

- **节点 B 增强**：引注方案不再默认"法学引注手册"，而是基于 `citation-crossref.py` 样本先**推断**作者实际使用方案
- **节点 E 新增**：是否对报告匿名化（U9）
- 自动推进模式（用户不在电脑前）下的保守原则更明确

---

## 索引

- 节点 A：确认论文类型
- 节点 B：确认引注校对方案（v2 强化）
- 节点 C：超大论文分章（仅 > 15 万字触发）
- 节点 D：是否生成批注文档
- **节点 E（v2 新增）**：是否匿名化报告
- §5 自动推进模式的保守原则（v2 新增）

## §A 节点 A：确认论文类型

### A.1 触发时机

在输入采集完成、§2 元信息清单发出之后；在节点 B 之前。

### A.2 默认值

**基于元数据推断的论文类型**。推断规则：

1. 若 `dc:title` 或首页含"硕士学位论文 / 专业硕士 / 学术硕士 / 法律硕士" → 硕士
2. 若 `dc:title` 或首页含"博士学位论文" → 博士
3. 若 `dc:title` 或首页含"本科毕业论文 / 学士学位论文" → 本科
4. 若有"投稿 / 期刊"特征 → 期刊投稿
5. 否则 → 不确定

### A.3 询问模板

```
论文类型自动推断为"{type}"（依据：{reason}）。请确认：
A) 本科 / B) 硕士 / C) 博士 / D) 期刊投稿 / E) 不确定
回复选项字母或"用默认"。
```

## §B 节点 B：确认引注校对方案（v2 强化）

### B.1 触发时机

节点 A 后、调用 TR / CC 前。

### B.2 默认值（v2 新）

**基于 citation-crossref 样本的自动推断**：

- 在进入节点 B 前，`citation-crossref.py` 已抽取了若干脚注样本
- Agent 从样本中读取 5-10 条典型脚注，判断作者实际体例：
  - 含 `[M] / [J] / [C]` 文献类型标识 → GB/T 7714—2015
  - 含"《……》，作者：……，出版社 YYYY 年版，第 X 页" → 法学引注手册
  - 两者都有或都不完全符合 → "学校自定义 / 需用户确认"
- 推断明确时 → 按该方案校对
- **推断不明时 → 默认"同时按两种方案呈现对比"**（v1 的默认值"法学引注手册"改为此）

### B.3 询问模板

```
引注方案自动推断为"{scheme}"（依据：{reason}）。请确认：
A) GB/T 7714—2015（国标）
B) 法学引注手册（法学期刊推荐）
C) 同时按两种方案呈现对比（v2 默认，推断不明时）
D) 学校自定义格式（请提供格式规则文档链接）
```

### B.4 响应解析

| 用户输入 | 解析 |
|---|---|
| `A` / `国标` / `7714` | 方案 A |
| `B` / `手册` / `法学引注手册` | 方案 B |
| `C` / `都要` / `两个都` / 空回复（不明） | 方案 C 两方案对比 |
| `D` / `学校` | 方案 D，要求用户补提供格式规则 |

## §D 节点 D：是否生成批注文档

### D.1 触发时机

§7 合并输出完成、issues.json 自校验通过后。

### D.2 默认值

**生成**（自动推进模式下默认执行）

### D.3 询问模板（v2：pdf 路径改用 annotate-pdf）

**pdf 输入**：

```
Markdown 报告与 issues.json 已生成。是否生成嵌入式批注 pdf？
A) 生成（默认，输出 {原名}.annotated.pdf，任何阅读器直接打开可见批注）
B) 不生成（仅交付 MD + JSON）
```

**docx 输入**：

```
Markdown 报告与 issues.json 已生成。是否生成批注 docx 副本？
A) 生成（默认，输出 {原名}.annotated.docx）
B) 不生成（仅交付 MD + JSON）
```

### D.4 响应解析

| 用户输入 | 解析 |
|---|---|
| `A` / `生成` / `要` / 空回复 | 生成 |
| `B` / `不生成` / `不要` | 不生成 |

## §E 节点 E（v2 新增）：是否匿名化报告

### E.1 触发时机

节点 D 后、报告正式输出前。

### E.2 默认值

**不匿名**（作者本人审查自己论文的场景无需匿名）

### E.3 询问模板

```
是否对报告进行匿名化（作者姓名 / 单位 / 指导教师隐去）？
A) 不匿名（默认，报告中显示完整信息）
B) 匿名化（报告中用 {{author}} / {{institution}} / {{supervisor}} 占位符代替）
```

### E.4 响应解析

| 用户输入 | 解析 |
|---|---|
| `A` / `不匿名` / `不要` / 空回复 | 不匿名 |
| `B` / `匿名` / `匿名化` / `隐去` | 匿名化 |

### E.5 匿名化规则

选"匿名化"时，MD 报告、issues.json、批注 pdf **一致地**用占位符：

| 字段 | 占位符 |
|---|---|
| 作者姓名 | `{{author}}` |
| 培养单位 | `{{institution}}` |
| 指导教师 | `{{supervisor}}` |
| 学号 | `{{student_id}}` |
| 完成日期 | `{{completion_date}}` |
| 其他真实案件当事人 | `{{case_party_N}}` |

**注意**：匿名化仅对**个人信息**适用，对论文中引用的**公开学者姓名**（如"王利明、孙宪忠"等已发表著作）**不匿名化**——这些是学术引用，不属于隐私。

## §5 自动推进模式的保守原则（v2 新增）

当用户明示"自行推进 / 不在电脑前 / 按默认执行"时，Agent 应当：

### 5.1 启动前明确公告

报告开头必须有小节：

```markdown
## 自动推进模式声明

本次审查在自动推进模式下执行，4 个交互节点采用以下默认值：

- 节点 A（论文类型）：{type}（依据：{reason}，置信度：高/中/低）
- 节点 B（引注方案）：{scheme}（依据：{reason}，置信度：高/中/低）
- 节点 C（分章）：{chapter_split}（篇幅 {words} 字，未触发此节点 / 已按章拆分）
- 节点 D（批注）：{annotate}（默认生成）
- 节点 E（匿名）：{anonymize}（默认不匿名）

如果任何节点推断与用户期望不符，请告知 Agent 重新执行对应环节。
```

### 5.2 推断低置信时**双呈现**

任何节点推断**置信度为"低"**时，自动启用"双呈现"策略：

- 节点 A 低置信 → 按"硕士"与"不确定"两档标准**并列输出**评价
- 节点 B 低置信 → 按"GB/T 7714"与"法学引注手册"两方案**并列输出**引注校对问题
- 用户回归后可按实际方案筛选

### 5.3 致命指控保守化

自动推进模式下，`severity=fatal` 的 issue **自动降级**为 `major`，除非满足以下全部条件：

1. 已联网核实（有 URL 证据）
2. 证据链闭环（原文 + 联网 + 规则依据）
3. 是客观事实性错误（非主观判断）

**降级原因**：自动模式下用户无法实时修正误报，保守是更负责任的默认。

### 5.4 报告末尾附"可信度表"

报告末尾必须附：

```markdown
## 指控可信度表

本报告共 N 条指控，按可信度分布：

| 级别 | 数量 | 说明 |
|---|---|---|
| 高可信度（联网核实 + 证据闭环） | X |
| 中可信度（文本分析 + 规则依据） | Y |
| 低可信度（仅 grep/推断） | Z |

用户回到电脑前时，建议按从高到低可信度优先核对。
```

## §6 通用约定（与 v1 一致）

- 默认值在用户回复"用默认/看你/你决定"或空回复时自动采用
- 每节点重复询问上限 1 次，第二次仍不命中则走默认
- 节点 A+B 可合并在一条消息（减少往返）
- 节点 C/D/E 各自独立触发，不合并
- 用户主动中断（"取消/停"）→ 保存已有产物
