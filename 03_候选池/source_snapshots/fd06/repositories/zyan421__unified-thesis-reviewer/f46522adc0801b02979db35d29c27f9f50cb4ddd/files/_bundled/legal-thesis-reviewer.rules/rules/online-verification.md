# 联网核实工作流与"四步式"呈现规范

> 本 skill 的一大核心要求：**只要当前环境存在任何可用的联网工具**，对论文中引用的可查证事实（法律、法条、案例、数据、学者身份、文献存在性等）必须**主动调用**进行核实，并按"**具体页码—原文复述—联网核实结果—学理判断**"的四步式呈现。

---

## 一、联网工具识别

在开始核实前，先做工具可用性扫描。**任何一种**以下工具的存在都应视为"具备联网能力"：

### 1.1 原生工具名（可能出现在不同平台的不同名字）

- `web_search` / `remote_web_search` / `search_web` / `google_search` / `bing_search` / `baidu_search`
- `web_fetch` / `fetch_url` / `browse_url` / `http_get`
- `scholar_search`（学术搜索）
- `firecrawl_*` / `crawl_*`（网页抓取）
- `puppeteer_*` / `playwright_*`（浏览器自动化）

### 1.2 各平台 MCP / 插件注入的工具

- MCP 服务器注入的工具，工具名中含 `search`、`web`、`browse`、`fetch`、`crawl`、`scrape`、`google`、`bing`、`baidu`、`scholar`、`wiki`、`news`、`law`、`legal`、`case`、`court`、`judgment`、`裁判文书`、`北大法宝`、`威科先行`、`ncac`、`pkulaw` 等
- Coze / Hermes / OpenClaw / IMA 等平台的插件能力

### 1.3 第三方客户端注入

- 代理转发的搜索能力（如通过 mcp-proxy 转发的各类搜索服务）

### 1.4 操作流程

1. **先尝试识别**：扫描当前 session 可用的工具列表，识别上述任一类工具
2. **先做小规模测试**：选取论文中一条**最容易核实**的信息（如"《民法典》第 1260 条是施行日期条款"），进行一次联网核实，确认工具真实可用
3. **确认后批量核实**：按 §三 的"核实对象优先级清单"批量处理
4. **若无联网工具**：按 §四 的"离线标记流程"处理

## 二、核实对象优先级清单（必核事项）

按"最重要 → 较重要"排序，在时间允许的情况下逐项核实：

### 优先级 P0（必核、不可跳过）

1. **案号真实性**：论文引用的每一个裁判文书案号，对应的文书是否真实存在？法院、案由、当事人是否与论文描述一致？
2. **典型案例真实性**：所称"最高法/最高检发布的典型案例""指导性案例""十大案例"是否真实存在？
3. **关键统计数据**：摘要或核心论证中的百分比、增长率、绝对数是否有真实的官方出处？

### 优先级 P1（高优先，强烈建议核实）

4. **法律名称与条文号**：被反复援引的 X 法第 Y 条，内容是否与现行法一致？
5. **司法解释**：法释〔XXXX〕X 号是否被作者准确标注？是否已被新规范废止？
6. **发文机关**：重要规范性文件的发文机关是否完整、准确？

### 优先级 P2（中优先，重点抽查即可）

7. **学术文献存在性**：作者 + 篇名 + 期刊 + 年份 + 卷期 + 页码 的组合是否真实存在？
8. **人物身份**：所称"教授""院士""法官"的任职机构、头衔是否属实？
9. **外文立法 / 判例**：外国法条款、案件名称、法院名称是否准确？

### 优先级 P3（按情况）

10. **历史事实**：时间、事件、人名的匹配
11. **技术细节**：特定技术标准、算法名称、行业数据

## 三、"四步式"呈现规范

每个核实项严格按以下格式呈现：

```
【核实项 N】（标题，用一句话概括核实对象）

① 具体定位
   章节：§X.X.X
   页码：第 Y 页 / 第 Y 页第 Z 段
   （若无页码信息，按章节号定位）

② 原文复述
   论文原文写道："…………"（原文直接引用，≤ 30 字，用双引号）

③ 联网核实结果
   - 工具：[使用的工具名]
   - 查询：[查询词/URL]
   - 检索到的真实情况：
     * 核实要点 1：……
     * 核实要点 2：……
   - 来源：[URL / 官方数据库 / 裁判文书网编号 / 出版社 ISBN 等]
   - 核实日期：[当前日期]
   - 不一致处：
     * 论文说"A"，实际为"B"（请提供具体细节）

④ 学理判断
   - 问题性质：[事实性错误 / 伪注 / 过时信息 / 以讹传讹 / 数据造假线索 / 无法核实]
   - 严重程度：[轻微 / 一般 / 严重 / 学术不端风险]
   - 对论文主体论证的影响：……（是否动摇核心论点）
   - 修改建议：
     1. ……
     2. ……
```

### 示例（模拟，假设论文中出现了张老师评阅过的某一类问题）

```
【核实项 3】论文对《反电信网络诈骗法》第 25 条的引用

① 具体定位
   章节：§2.3.1，以及全文共 10 处引用
   页码：第 18 页第 2 段

② 原文复述
   论文原文写道："《反电信网络诈骗法》第 25 条将'应当知道'作为主观认知的认定标准"

③ 联网核实结果
   - 工具：web_search
   - 查询：《中华人民共和国反电信网络诈骗法》第二十五条
   - 检索到的真实情况：
     * 《反电信网络诈骗法》第 25 条规定的是涉诈异常账户和可疑交易监测、核查、报告义务
     * 该条完全未涉及"应当知道"的主观认知认定
     * 关于"应当知道"的表述实际出现在《最高人民法院、最高人民检察院关于办理电信网络诈骗等刑事案件适用法律若干问题的意见（二）》等司法解释中
   - 来源：国家法律法规数据库（flk.npc.gov.cn）
   - 核实日期：2026-05-11
   - 不一致处：
     * 论文错误归因了条文号
     * 此错误在全文共出现 10 次

④ 学理判断
   - 问题性质：事实性错误 / 重大条文号误引
   - 严重程度：严重（核心论据错误，10 次重复同一错误）
   - 对论文主体论证的影响：论文第 X 章整章以"第 25 条规定了应当知道"为基础展开的论证失去了法律依据，该章需重写
   - 修改建议：
     1. 核实"应当知道"在反电信网络诈骗法律体系中的实际规范依据
     2. 如确指上述司法解释，应改为引用该司法解释及其具体条款
     3. 全文搜索"《反电信网络诈骗法》第 25 条"10 处，逐一更正
```

## 四、离线标记流程（无联网工具时）

当前环境**没有任何可用的联网工具**时：

### 4.1 在审查报告开头显著声明

```
⚠️ 联网能力缺失

本次审查运行在不具备联网工具的环境中。以下候选核实项**未经联网核实**，仅作标记，
**请用户自行核对**，或在具备联网工具的环境中重新运行本 skill。
```

### 4.2 按四步式的"前两步 + 待核实"呈现

对每个候选核实项仍列出：
- ① 具体定位
- ② 原文复述
- ③ 联网核实结果：**⚠️ 待核实**
- ④ 建议的核实方法（如 "请到中国裁判文书网以案号 XX 检索"；"请到国家法律法规数据库以关键词 XX 检索"）

### 4.3 输出候选核实清单

在报告末尾附"**待核实项清单**"：

```
待核实项清单（建议在具备联网能力的环境中完成核实）：
1. 论文 §X.X.X "案号 (2023)鲁02民终456号" 是否为离婚经济补偿案件
2. 论文 §X.X.X 引用的"李显冬《论个人信息保护法中的惩罚性赔偿制度》（法学家2022.04）"是否真实存在
3. 论文 §X.X.X "2024 年最高法推定适用十大案例"是否真实发布
...
```

## 六、核实纪律

1. **不编造核实结果**：没有检索到的内容不要臆测，明确标"**未检索到**"或"**待核实**"
2. **保留原始证据**：每一条核实结果要能追溯到具体的查询和来源链接
3. **核实范围不超出本 skill 的职能**：本 skill 核实论文**引用的具体事实**，不对作者的**学术观点**进行对错评价；观点的评价在第三 ③ 维度（论证深度）中体现
4. **尊重隐私**：核实裁判文书时不在审查报告中复述真实当事人姓名 / 身份证号，仅保留案号和概括性描述
5. **网络信息可能滞后或错误**：对核实结果本身仍需交叉验证（至少 2 个来源）
6. **不是每一条都需要联网核实**：对于**无须联网也能看出对错**的错误（如文字错误、语病、自相矛盾），直接标注即可，无需绕一圈联网核实
