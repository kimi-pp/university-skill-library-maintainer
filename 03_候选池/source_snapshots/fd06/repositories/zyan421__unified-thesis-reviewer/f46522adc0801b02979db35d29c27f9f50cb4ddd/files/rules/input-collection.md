# 输入采集与格式识别

本文件定义 `unified-thesis-reviewer` 在 §2 输入采集阶段的各采集路径、异常形态的拒绝话术、元信息反馈清单。本文件是 `rules/orchestration-flow.md` §2 的展开。

## 索引

- 6 类输入形态的采集路径：§1
- 异常形态的拒绝话术：§2（扫描件）、§3（加密 docx）、§4（损坏文件）
- 元信息反馈清单：§5（至少 7 项字段）
- 采集流程图：§6

## §1 六类输入形态的采集路径

### 1.1 docx 输入（最常见）

- 调用 `tools/extract-docx.py` 读 `word/document.xml`，保留段落边界
- 仅使用 Python 3.8+ 标准库（`zipfile` + `xml.etree.ElementTree`），不依赖 python-docx
- 提取粒度：每个 `<w:p>` 元素对应一段；表格内段落按 `<w:tbl>` / `<w:tr>` / `<w:tc>` 层级抽取并记录 `table_index`、`row`、`col`、`paragraph_index_in_cell`（为 v2 批注定位做准备）
- 保留页眉、页脚、脚注、尾注、批注部件**本身**不纳入 `paragraph_index` 的计数（仅 `document.xml` 中 body 直属 `<w:p>` 计入）
- 同步抽取脚注部件 `word/footnotes.xml` 与尾注部件 `word/endnotes.xml`，供 CC 使用

### 1.2 文本版 pdf 输入

- 先**探测文本层**：提取 pdf 全文，统计可见字符数
- 文本层字符数 ≥ 200 → 视为文本版 pdf，进入正常采集
- 文本层字符数 < 200 → 触发扫描件拒绝路径（§2）
- 文本层提取能力由宿主环境提供（平台内置 pdf 解析 / MCP 的 pdf 工具 / Agent 已安装的 pdf 处理库）；本 skill 自身不内置 pdf 文本抽取脚本
- 若宿主环境完全不具备任何 pdf 解析能力，按 `rules/error-handling.md` 第 4 类错误处理（建议转 docx 或粘贴纯文本）

### 1.3 扫描件 pdf（拒绝路径）

- **阈值**：pdf 文本层字符数 **< 200** 字符
- 话术见 §2

### 1.4 加密 docx（拒绝路径）

- 识别方式：用 `zipfile.ZipFile(path)` 打开时捕获到密码相关错误；或 docx 内含 `EncryptedPackage` OLE 流（Office 2007+ 加密容器的典型标志）
- 话术见 §3

### 1.5 纯文本片段（无原始文件）

- 用户直接在消息中粘贴论文片段或全文，没有上传任何 docx/pdf 文件
- 继续执行 v1 的文本分析与 Unified_Report 生成
- **在 MD 报告头部**显著标注：

  > ⚠️ 未提供原始文件，v2 批注文档与 v3 XFDF 旁路文件不可用；本次仅交付 Markdown 报告与 `issues.json`。

- 节点 D（§7）在这种输入形态下**直接跳过**，不询问用户是否生成批注

### 1.6 超大篇幅（> 10 万字）

- 在采集阶段就启用**分章采集模式**：按 `<w:pStyle w:val="Heading1/2">` 或其他章节标题样式切分，单章独立存入内存结构
- 避免一次性把全文装入上下文导致溢出
- 是否**在主流程中**额外询问用户"按章拆分"由篇幅分档决定（阈值 15 万字，详见 `rules/size-tier.md` 与 `rules/orchestration-flow.md` §3A）

## §2 扫描件 pdf 的拒绝话术

阈值触发（**文本层 < 200 字符**）时，输出以下消息并**终止**流程，不进入后续步骤：

```
检测到 pdf 的可提取文本层仅 {N} 个字符，判定为扫描件。
本 skill 不自动执行 OCR，请按以下任一方式处理后重试：

1. 在 Adobe Acrobat / ABBYY FineReader / WPS 等工具中对 pdf 做 OCR，导出可搜索文本的 pdf 或 docx
2. 直接用 Word 打开 pdf（Word 自带 OCR），另存为 docx
3. 把论文全文复制到聊天窗口，以纯文本方式提交（v2/v3 批注不可用）

完成后可重新发起审查请求。
```

不要尝试猜测扫描件内容，不要降级为"粘贴前 200 字"模式。

## §3 加密 docx 的拒绝话术

识别到加密 docx 时，输出以下消息并**终止**流程：

```
检测到加密的 docx 文件，本 skill 无法读取其内容。
请按以下步骤去除密码保护后重新提交：

1. 在 Word 中打开该文件（需输入密码）
2. 菜单：文件 → 信息 → 保护文档 → 用密码进行加密 → 删除密码框内字符 → 确定
3. 另存为（或覆盖保存）
4. 把去除密码后的 docx 重新上传

如果你不方便去除密码保护，也可以直接把论文全文以纯文本方式粘贴到聊天窗口（但 v2 批注文档将不可用）。
```

不要尝试暴力破解，不要请求用户在聊天中提供密码（见 steering rule `secrets-in-chat-reflex.md`）。

## §4 损坏文件的处理

### 4.1 docx 损坏

- 识别方式：`zipfile.BadZipFile` 异常、`xml.etree.ElementTree.ParseError` 异常、或 `[Content_Types].xml` 缺失
- 按 `rules/error-handling.md` 第 3 类错误处理：建议"在 Word 中另存为 docx 后重试，或粘贴纯文本"

### 4.2 pdf 损坏

- 识别方式：pdf 头不以 `%PDF-` 开头、MediaBox 解析失败、xref 表错乱
- 按 `rules/error-handling.md` 第 4 类错误处理：建议"转 docx 后重试，或直接粘贴纯文本"

## §5 采集后元信息反馈清单（至少 7 项）

采集完成后、节点 A 询问之前，以**单条消息**向用户反馈以下元信息清单。所有字段都要给出，缺失的显式写"未识别 / 待用户确认"。

| 字段 | 取值说明 | 示例 |
|---|---|---|
| 1. 题目 | 从首页或第一节大标题推断 | "论行政处罚听证程序的完善" |
| 2. 论文类型 | 本科 / 硕士 / 博士 / 期刊投稿 / 不确定 | "硕士学位论文（推断）" |
| 3. 篇幅 | 按全文字符数折算为万字 | "约 3.8 万字" |
| 4. 章节数 | 一级章节数，二级分章节不计 | "共 4 章" |
| 5. 脚注总数 | 整篇 `<w:footnote>` 计数或粘贴版按引注标记计数 | "47 条脚注" |
| 6. 参考文献条数 | "参考文献"一节下的条目数 | "31 条" |
| 7. 是否具备页码信息 | docx 有页码字段 / pdf 本身有页码 / 纯文本无页码 | "有页码" |
| 8. 输入形态 | docx / pdf / text（纯文本片段） | "docx（原始文件已上传）" |

示例模板（直接发给用户）：

```
已完成采集，反馈论文元信息如下——

- 题目（推断）：XXX
- 论文类型（推断）：XXX
- 篇幅：约 X 万字
- 章节数：X 章
- 脚注总数：X 条
- 参考文献：X 条
- 页码信息：有 / 无
- 输入形态：docx / pdf / 纯文本片段

接下来将进入确认节点，请问论文类型的推断是否正确？【详见 templates/interaction-prompts.md 节点 A】
```

第 2 项（论文类型）的推断方法：优先看"学位论文"、"毕业论文"、"硕士论文"、"博士论文"等字样；其次看署名与章节数（博士常为 6+ 章、硕士 4–5 章、本科 3–4 章）；都不可得则填"不确定"，默认值由节点 A 处理。

## §6 采集流程图（文本版）

```
用户提交输入
  │
  ├─ 输入是 docx ────────┐
  │                       │
  │  解压 zip             │
  │   │                   │
  │   ├─ 加密 → §3 拒绝话术 → 终止
  │   ├─ 损坏 → §4.1 错误处理 → 终止
  │   └─ 成功                │
  │       │                   │
  │       └─ 读 document.xml → 结构化段落 → §5 元信息 → 节点 A
  │
  ├─ 输入是 pdf ────────┐
  │                       │
  │  探测文本层           │
  │   │                   │
  │   ├─ < 200 字符 → §2 拒绝话术 → 终止
  │   ├─ 损坏 → §4.2 错误处理 → 终止
  │   └─ ≥ 200 字符          │
  │       │                   │
  │       └─ 提取全文 → 结构化段落 → §5 元信息 → 节点 A
  │
  ├─ 输入是纯文本片段 ──┐
  │                       │
  │  直接使用 → §5 元信息 + "v2/v3 不可用" 警告 → 节点 A
  │
  └─ 输入 > 10 万字 ────┐
                          │
  按章采集模式（每采一章一个内存单元）→ §5 元信息 → 节点 A
```

---

## §7 采集阶段不做的事

- **不**对内容作任何评价（那是 §4 TR 的职责）
- **不**对引注作任何校对（那是 §5 CC 的职责）
- **不**调用联网工具（联网核实只发生在 §4 TR 流程中）
- **不**向用户询问除"扫描件 / 加密 / 损坏"之外的问题；节点 A/B 在采集完成后才发起

采集阶段唯一的"主动输出"就是 §5 的元信息清单。
