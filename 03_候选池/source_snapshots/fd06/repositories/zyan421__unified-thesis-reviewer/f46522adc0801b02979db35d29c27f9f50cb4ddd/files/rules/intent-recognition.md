# 意图识别规则

本文件定义 `unified-thesis-reviewer` 激活时如何在 **Unified（一站式）**、**仅 TR**（只走 `legal-thesis-reviewer`）、**仅 CC**（只走 `legal-citation-checker`）三类意图之间分派。本文件是 `rules/orchestration-flow.md` §1 的展开。

## 索引

- 三类意图触发词白名单：§1
- 消歧原则：§2
- 仅 TR / 仅 CC 的直接处理策略：§3、§4
- 边界模糊情形：§5

## §1 三类意图触发词白名单

匹配方式为**子串包含**（不区分中英文大小写），命中任一即视为落入对应类别。同一条用户消息可能同时命中多个类别，按 §2 消歧。

### 1.1 Unified（一站式）触发词

用户想要"深度审查 + 引注校对"**一次完成**：

- 一站式 / 一站式审查 / 一次性检查 / 一次到位
- 全面审查 / 综合审查 / 综合审阅 / 全面检查
- 批注版 / 带批注的修订稿 / 带批注稿 / 原稿批注
- 盲审式全面检查 / 模拟盲审 / 盲审稿自查
- 同时查 / 一起查 / 一并检查 / 都帮我看一下
- 未定稿检查 / 论文未定稿检查
- thesis all-in-one review / unified thesis review / annotated thesis / end-to-end review

命中任一 → 候选类别 **Unified**。

### 1.2 仅 TR 触发词

用户想要**仅**做论文内容审查，且明确或隐含"不关心引注格式"：

- 论文内容审查 / 论文深度审查 / 论文深审
- 挑毛病 / 挑问题 / 找问题 / 指出论文不足
- 盲审 / 盲审评阅 / 写一份评阅意见 / 评阅书
- 像张老师那样审 / 张老师评阅 / 按张老师标准
- 问题意识 / 论证深度 / 文献综述 / 学术不端
- law thesis review / thesis critique / peer review

并且消息中**含** "不关心引注"、"不用查格式"、"引注先不管"、"格式以后再说"等显式排除；或消息中**完全未提**引注 / 脚注 / 参考文献 / 格式。

命中 → 候选类别 **仅 TR**。

### 1.3 仅 CC 触发词

用户想要**仅**做引注格式校对，且明确"只做格式"：

- 引注校对 / 引注规范 / 引注格式 / 引注检查
- 脚注格式 / 脚注规范 / 脚注校对
- 参考文献格式 / 参考文献规范 / 文献格式
- GB/T 7714 / GB 7714 / 7714 / 国标
- 法学引注手册 / 引注手册
- citation check / footnote format / bibliography check

并且消息中**含** "只做格式"、"只看格式"、"只校对"、"不用审查内容"、"格式就行"等显式限定；或整条消息的语义完全聚焦于格式规范而不涉及内容评价。

命中 → 候选类别 **仅 CC**。

## §2 消歧原则

### 2.1 同时命中 Unified 与 仅 TR / 仅 CC → **优先 Unified**

当用户消息同时命中 Unified 触发词与 §1.2 / §1.3 的触发词（例如"帮我一站式审查，顺便按 GB/T 7714 校对引注"），**一律判为 Unified**，由本 skill 全流程编排。这是 R14.3 的默认优先级。

理由：Unified 的产物包含仅 TR / 仅 CC 能提供的全部内容，不会"少做"；但反过来单独调用底层 skill 会遗漏另一类检查。

### 2.2 同时命中 仅 TR 与 仅 CC → 升级为 Unified

例如消息同时含"挑毛病"与"查一下参考文献格式"，且没有命中 Unified 触发词。此时判为 **Unified**，在 §3 节点 A 之前向用户简短说明"将按一站式流程执行，同时覆盖内容审查与引注校对"。

### 2.3 仅命中 仅 TR 或 仅命中 仅 CC → 直接委托底层 skill

不走本 skill 的 7 步流程。按 §3 / §4 处理。

### 2.4 三类都未命中但消息模糊

例如"帮我看看这篇论文"。此时保守判为 **Unified**（本 skill 的默认态），进入 §2 采集流程，由采集完成后的元信息清单 + 节点 A 询问将判断权交给用户。

### 2.5 消歧冲突的记录

每次判定后，在流程启动消息的"流程计划说明"里一并告知用户当前走哪条路径。这样用户能在第一时间纠正。

## §3 仅 TR 的直接处理策略（R1.3）

- 激活 `legal-thesis-reviewer`，完整走它的 7 步工作流
- Unified_Reviewer **不介入**也**不合并**，TR 的产物直接交付给用户
- 在 TR 产出的报告末尾**追加一行**（不要漏）：

  > 本次仅执行论文深度审查；如需引注格式校对或一站式全面检查，可再次发起请求。

- 即便 TR 的工作流中涉及联网核实（TR 第 4 步），本 skill 的 `rules/online-verification-unified.md` **不**参与——那份文件只在走 Unified 路径时才替换 TR 的联网核实环节

---

## §4 仅 CC 的直接处理策略（R1.2）

- 激活 `legal-citation-checker`，完整走它的 5 步工作流
- Unified_Reviewer **不介入**也**不合并**，CC 的产物直接交付给用户
- 在 CC 产出的报告末尾**追加一行**（不要漏）：

  > 本次仅执行引注格式校对；如需论文内容审查或一站式全面检查，可再次发起请求。

- CC 自身的"第 2 步：确认校对方案"照常执行，不走本 skill 的节点 B

---

## §5 边界模糊情形的处理

### 5.1 用户只说"审查论文"且上传了 docx

审查一词在 TR 与 Unified 之间都能匹配。此时：

- 如果同一条消息**明确**含"引注"或"参考文献"或"格式"相关词 → 判 Unified
- 否则 → 默认 Unified（走 7 步编排），让 §3 节点 A 之前的元信息反馈触发用户的进一步指令

### 5.2 用户说"帮我看下这个脚注对不对"

即使含"脚注"，语义聚焦在某一条的**正误**（含事实 / 时效），不是**格式校对**，此时：

- 倾向 **Unified**（因为单点事实核实涉及联网核实，TR 的第 4 步负责）
- 若用户随后明确说"我只关心格式是否合规" → 切换到 **仅 CC**

### 5.3 用户上传的文档篇幅极短（< 2000 字）或仅粘贴片段

不改变意图判断，但在 §2 采集阶段标注"仅 v1 可用，v2/v3 批注生成不可用"（R2.5）。

### 5.4 用户使用明显非学术语境（如"帮我看看我写的笔记"）

按 R15.5 处理：进入采集阶段后，若识别为非法学论文，询问是否继续按法学论文审查标准执行。意图判定本身仍按 Unified 处理。

## §6 与底层 skill 关键词撞车的说明

TR 的 keywords（如"论文审查""盲审"）与本 skill 的 keywords（如"全面审查""一站式"）有重叠——宿主平台同时加载三个 skill 时，本 skill 的 `depends_on` 字段与 R14.3 的"同时命中优先 Unified"一起确保编排层先获得执行权。

若宿主平台不支持 `depends_on` 语义，仍应按 §2.1 在 Agent 侧做路径裁决；底层 skill 不会被修改，其独立可激活性不受影响（R14.1）。
