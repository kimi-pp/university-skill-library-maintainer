# 0809 计算机类跨平台技能调研 Implementation Plan

> **For agentic workers:** 本计划在当前任务内顺序执行；遵守用户限定，不派生子任务，不安装或运行候选 skill。

**Goal:** 面向 0809 计算机类的 14 个本科专业，跨公开开源平台发现、去重、静态安全审查并整理可用于高校学生及员工辅助系统的 skills，形成一套可复用的学科打样方法和独立交付物。

**Architecture:** 以“专业—共享能力群—skill”为三层映射，候选先经过来源与上游核验，再进入说明、包结构、脚本、依赖和权限的静态安全审查。只有通过安全准入的候选进入规范数据、知识库、Excel 和 Word；落选项仅在内部归档。

**Tech Stack:** 公开代码平台与可追溯 skill registry、平台 API/网页读取、Python 规范数据和 DOCX、`@oai/artifact-tool` XLSX、Markdown 索引、静态文本与目录审查。

## Global Constraints

- 学科范围：仅 `0809 计算机类`，覆盖源目录所列 14 个专业。
- 来源范围：GitHub、GitLab、Codeberg、Gitee、SourceHut、Hugging Face 公开仓库，以及能回溯到版本化公开源仓库的开放 skill registry/集合。
- registry、精选列表和搜索引擎只用于发现；正式证据必须落到可读取的公开源码、skill 包或版本化目录。
- 候选形态：结构化 `SKILL.md`、agent skill/plugin/command、可移植工作流，以及能够合理封装为 skill 的公开任务模板。
- 普通软件库、模型、MCP 或 API 不单独作为 skill；只有存在明确 agent 工作流或 skill 包装时才作为主体候选，否则仅作关联资源。
- 正式候选必须通过 `SECURITY_REVIEW_PROTOCOL.md` 的静态安全准入；无法审查、明显恶意或高风险默认行为的条目不得进入正式报告。
- 初筛阶段不安装、不运行、不调用候选外部服务、不输入账号或校内数据。
- 安全结论只写“静态安全审查通过/受限通过/不通过”，不得写“绝对安全”。
- 生态、来源平台、来源形态和安全等级分别标注。
- 每轮由用户限定范围；本计划不会扩展到 0809 之外的其他一级学科。
- 正式交付：独立 Excel、独立 Word、Markdown 知识库、跨专业映射表和静态安全验证记录。

## Self-Review

- 规格覆盖：0809、跨开放平台、14 个专业、安全准入、排除不进报告、独立双格式交付和知识库均有对应任务。
- 范围边界：不扩展其他一级学科；registry 不能替代可审计上游；普通软件库不冒充 skill。
- 安全边界：静态审查与运行安全分开，不能用“未发现问题”表达绝对安全。
- 执行方式：当前任务内顺序执行，不派生子任务；候选安装和运行等待用户对具体对象另行授权。
