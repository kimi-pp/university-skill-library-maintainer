## 通用小分类与通俗派生字段

这些字段只服务五个通用大分类的细分样板，不用于细分专业或学科分类。派生字段由原始事实记录和批准的小分类归属表生成，不回写原始五类 JSON。

| 字段 | 内部字段名 | 必填 | 含义与填写规则 |
|---|---|---:|---|
| 小分类代码 | `subcategory_code` | 是 | 格式为 `大分类代码-两位序号`，例如 `01-01`；必须与内部标识的大分类一致 |
| 小分类名称 | `subcategory_name` | 是 | 使用批准的中文名称，不自行改名或合并 |
| 小分类收录重点 | `inclusion_focus` | 是 | 用一句通俗中文说明这一小类主要解决的任务 |
| 唯一主分类 | `assignments[内部标识]` | 是 | 每项 Skill 只对应一个小分类；以主要产出和任务用途决定归属 |
| 辅助标签 | `tags` | 是 | 保留主用途以外的能力，供检索和说明使用；不形成第二个主分类 |
| 通俗主要用途 | `plain_purpose` | 是 | 说明“它能帮您做什么”，不得只复述产品宣传语 |
| 通俗主要产出 | `plain_outputs` | 是 | 说明使用后会得到什么具体材料、结果或记录 |
| 通俗适用人员 | `plain_audience` | 是 | 说明适合哪些学生、教师、科研或行政与专业支持人员 |
| 通俗适用场景 | `plain_when_to_use` | 是 | 说明什么情况下值得使用，避免只写抽象领域 |
| 通俗使用前准备 | `plain_prerequisites` | 是 | 说明需要准备的材料、账号、软件、权限或技术支持 |
| 通俗限制 | `plain_limitations` | 是 | 说明数据、权限、外部服务、维护和适用范围等限制 |
| 通俗接入说明 | `plain_integration` | 是 | 用白话说明接入现有工作台需要多少调整及建议做法 |
| 通俗核验说明 | `plain_verification` | 是 | 只说明本次核对到了说明或包内容，并明确候选未安装、未运行 |

### 事实保真边界

- 原内部编号、英文名称、软件名、来源 URL、核验状态、许可证、仓库关注数和最近更新时间必须逐项保留，不得因通俗改写而改变。
- “说明已核验”表示看过功能说明；“包内容已核验”表示进一步看过目录或文件内容。两者都不等于安装或运行成功。
- 候选、未安装、未运行的 Skill 不得写成“已验证可用”“已经运行成功”或“已经证明有效”。
- 通俗字段不得补写原始资料没有支持的功能、产出、兼容性或安全结论。

## 内部排除字段

历史批次的排除记录保存在内部 Markdown 中。自动维护工作流可以把排除结果写入主台账“候选观察”，但必须使用非展示层级、结构化原因代码和中文说明，并将候选名称留空。最终 Word/Excel 只能汇总标准化原因及数量，不得列出排除项名称。

## 自动维护主台账扩展字段

“专业任务映射”的 `内部标识` 可指向“当前Skill”中的正式条目，也可指向“候选观察”中的条件候选或需适配候选。归属层级由对应实体表判定；映射本身不得把候选误写成可直接部署的正式 Skill。三级展示都必须由人工依据固定材料确认专业任务映射，不得从查询词或名称关键词自动生成。

“候选观察”字段如下：

| 字段 | 必填 | 含义与填写规则 |
|---|---:|---|
| 观察标识 | 是 | 本条观察的确定性唯一键；用于同一结论幂等更新，不作为候选身份的解析来源 |
| 内部标识 | 展示项、版本审查项必填 | 显式候选稳定身份；必须与受信审查决定的 `candidate_id` 一致 |
| 候选名称 | 条件/适配必填；排除项留空 | 原始或规范候选名称；排除项不得借此泄露名称 |
| Canonical source | 可追溯时必填 | 规范上游地址；市场页只有在能追溯到规范上游及具体 Skill 入口时才可作为跨平台别名 |
| Skill入口路径 | 有规范上游入口时必填 | 固定包内具体 `SKILL.md` 的规范相对路径；必须与受信 ReviewPacket 和快照清单精确一致 |
| 观察状态 | 是 | 条件候选、需适配候选、排除或 `attention_required` 等结构化状态 |
| 许可证 | 是 | 固定材料对应许可证事实；未知许可证可进入有明确限制的条件候选，不得正式推荐 |
| 记录日期 | 是 | 本轮可信日期，必须为合法 `YYYY-MM-DD`；展示和非展示结果都不得留空 |
| 原因 | 是 | 中文结论与限制；排除项使用标准化原因说明且不含候选名称 |
| 固定版本 | 有固定包或版本审查时必填 | commit SHA、tag 或其他不可变版本；用于识别已审拒绝版本，避免重复复审 |
| 固定版本内容指纹 | 有固定包时必填 | 从实际固定包字节及具体 Skill 入口构建的内容 SHA-256；不得只信来源声明值 |
| 验证证据位置 | 有固定包或来源观察时必填 | 只列本候选实际出现的请求事件、固定包和入口文件证据，不得借用其他候选证据 |
| 原因代码 | 排除/异常观察必填 | 结构化原因，例如固定包不可得、入口已删除或安全禁止 |
| 显示层级 | 是 | 条件候选、需适配候选或不展示；不得与观察状态和部署边界冲突 |

同一 GitHub 仓库内每个可识别 `SKILL.md` 入口是独立 Skill 身份。正式条目的 `上游项目地址 + Skill入口路径` 必须唯一；同仓库不同入口不得合并，市场条目也必须绑定相同的上游和入口后才能去重。

“来源别名”的 `固定版本` 保存别名关系已经审查过的不可变版本。内容相同但上游 commit 变化时，当前 Skill 的固定版本保持原值，同时写入版本别名及其固定版本；下一轮同一版本不得重复下载和人工复审，新版本才重新进入材料闸。

主台账中的 `验证证据位置`、版本历史的 `证据位置` 和候选观察证据只能指向公开固定地址，或已发布 generation `authority` 中的可移植相对路径。运行暂存目录不是持久证据位置；发布后来源请求证据、固定归档、逐入口快照及快照清单必须存在且哈希匹配，后续运行不得删除仍被引用的前代 generation。generation manifest 的长期字段仅为相对路径、SHA-256、字节数和逻辑角色，设备号、inode 与 mtime 仅用于本次运行内防替换，不得作为跨机器校验条件。旧候选观察缺少名称（非展示排除/关注项除外）、原因或合法记录日期时不自动猜填，必须先由 `repair-ledger` 或人工依据原证据补录。

## 功能分类 06 正式字段

分类 06 使用平台中立编号 `FD-06-四位序号`。面向普通用户的字段放在前面，技术追溯字段放在后面。

| 字段 | 必填 | 含义与填写规则 |
|---|---:|---|
| skill_id | 是 | `FD-06-0001` 起的连续编号，本轮唯一 |
| name | 是 | 原始技能或工作流名称 |
| primary_subcategory | 是 | 06-01 至 06-12 之一，每项只能一个 |
| secondary_tags | 否 | 其他辅助功能，不重复计算分类数量 |
| plain_function | 是 | 它能帮普通用户做什么，使用通俗中文 |
| audience | 是 | 适合的教师、助教、教学管理人员、学生或课程支持人员 |
| when_to_use | 是 | 值得使用的具体教学情境 |
| inputs | 是 | 使用者需要提供的材料 |
| outputs | 是 | 使用者会得到的结果 |
| limitations | 是 | 不能完成的任务和需要人工判断的部分 |
| sensitive_data | 是 | 是否接触作业、成绩、个人信息、未公开论文或审稿材料 |
| adoption_level | 是 | 可直接使用、需要少量调整、需要重新改造 |
| security_grade | 是 | 正式数据只允许 SA、SB、SB-A |
| security_plain | 是 | 用具体后果解释风险和限制 |
| verification_depth | 是 | 固定写明固定版本静态核验及未运行范围 |
| canonical_url | 是 | 原始上游或完整公开技能包地址 |
| fixed_version | 是 | 提交哈希、标签、发布版本或不可变存档标识 |
| verified_at | 是 | `YYYY-MM-DD` |
| license | 是 | 固定版本对应许可证；不明确时不得正式收录 |
| maintainer | 是 | 作者或维护组织 |
| network_behavior | 是 | 外部网站、上传、遥测和网络要求；未见时明确写出 |
| credential_behavior | 是 | 账号、密钥和登录要求；未见时明确写出 |
| file_behavior | 是 | 文件读取、写入、覆盖、删除或发布行为；未见时明确写出 |
| evidence_paths | 是 | 本地证据快照及公开固定版本地址，可多值 |

### 分类 06 内部落选字段

候选名称、发现地址、原始上游、拟定主要小分类、落选类型、通俗理由、安全等级、证据位置和核验日期。落选类型包括偏离范围、证据不足、许可证不清、无法固定版本、实质重复、SC 和 SX。
