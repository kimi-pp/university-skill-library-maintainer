# Skill 调研、筛选与分类标准工作流

规则版本：1.4  
生效日期：2026-08-19  
来源依据：工作区《Skill规则框架_v1.2-2026-8-11.docx》（文档正文标注 V1.1）

## 1. 规则地位与适用范围

本文件是本项目今后 Skill 发现、调研、筛选、排除、准入、分类、复核、评级、归档、推荐和持续更新的唯一权威工作流。

- 自生效日起，所有新增调研、补充调研、候选复核和存量条目更新均执行本流程。
- 已完成的历史成果不自动重算、不批量改名、不回写旧结论；条目被重新核验或更新时，才迁移到本流程。
- 用户可限定当轮学科、功能、平台、角色、验证深度和交付物。用户明确指令优先，但偏离本流程时必须在决策日志记录偏离范围、理由和影响。
- 本流程与旧规则冲突时，以本流程为准；`SOURCE_POLICY.md`、`TAXONOMY.md`、`VALIDATION_PROTOCOL.md`、`SECURITY_REVIEW_PROTOCOL.md`、`DATA_DICTIONARY.md` 和 `REPORTING_STANDARD.md` 只在不冲突时提供补充细节。
- 默认只做只读核验，不安装、不运行、不登录候选服务、不上传真实教学或科研数据。运行验证必须由用户明确指定候选、环境和范围。

## 2. 每轮任务启动记录

开始搜索前必须记录以下内容；缺少任何一项时先补齐或明确采用本流程默认值：

1. 学科门类、专业或跨学科范围。
2. 需要解决的功能任务和目标产出。
3. 适用人员：学生、教学人员、科研人员、行政人员，可多选。
4. 来源平台及是否获准扩展平台。
5. 验证深度：说明核验、包内容核验、干运行核验或用户授权实测。
6. 时间截点、访问日期和维护状态核验日期。
7. 正式交付形式、内部留痕形式和完成判据。
8. 本轮是否存在用户批准的流程豁免。

### 2.1 最新专业目录复核门

凡按学科门类、专业类或本科专业开展新增、补充或复审调研，必须在建立专业画像和搜索矩阵之前完成目录复核；本门为搜索前置条件，不得用旧索引直接启动联网发现。

1. 先核对教育部当前公开的最新《普通高等学校本科专业目录》及其发布通知，记录文件标题、发布日期、访问日期、公开地址和发布机构。
2. 保存或复用可验证的本地快照，记录文件 SHA-256；复用旧快照时必须重新确认公开地址仍指向当前最新目录，并记录本轮复核日期。
3. 将项目旧目录与现行目录按门类、专业类、专业代码和专业名称逐项比较，生成机器可读差异记录；不得只比较总数，也不得只在旧清单末尾追加新专业。
4. 对新增、撤销、改名、代码变化、专业类变化和跨门类调整分别记录；已调出目标门类的专业不得继续进入该门类检索范围。
5. 更新该门类的知识库索引、总索引和来源方法说明，同时保留旧目录及差异证据供追溯，不覆盖或伪装历史口径。
6. 冻结当轮范围合同，至少包含专业类顺序、全部专业代码和名称、来源快照哈希、复核日期及差异记录哈希；范围合同未通过唯一性、数量和来源核验时不得生成检索任务。
7. 教育部在执行期间发布新版目录时，立即暂停尚未完成的发现任务，重新执行本门并评估已取得候选是否需要重新归类。

本门只校订当轮目标范围，不自动重算其他已完成门类；其他门类在下一次新增、补充或复审时再迁移到最新目录口径。

### 2.2 十六个维度的实施优先级

维度优先级用于安排填写顺序，不表示低优先级维度可以在正式入库时永久缺失：

| 优先级 | 维度 | 执行要求 |
|---|---|---|
| A | 1 学科门类优先级、2 跨学科复用度、3 安全等级、4 适用人员 | 原始候选完成初筛时填写门类、复用度、人员和安全待核验状态/初步风险信号；第一阶段至少覆盖这四项，正式安全等级后补 |
| B | 5 接入难度、6 准备度、7 更新活跃度、8 质量评分、9 许可证合规 | 候选进入核验和排序前补齐 |
| C | 10 核验状态、11 平台来源、12 API 依赖可达性、13 排除规则、14 降级处理、15 归档分类层级、16 持续更新规则 | 作为完整流程、追溯和维护维度；正式入库前必须完成适用项 |

不得把“第一阶段优先完成 A 级维度”理解为正式入库只需四项。硬性排除、准入四条件、安全、许可证和来源追溯始终是不可绕过的门槛。

初筛阶段不得仅凭说明或平台卡片给出正式 `SA/SB/SB-A/X` 结论。此时安全字段只填 `待核验` 并记录已发现的初步风险信号；完成说明、包内容和静态干运行核验后才能写正式等级。后续证据改变结论时，保留原观察并记录修订日期和理由。

## 3. 标准流水线

所有调研按以下顺序执行，阶段结果不得混写：

1. **定义范围**：完成最新专业目录复核门和任务启动记录，冻结现行专业范围后，建立学科词、专业词、功能词、Skill 形态词和平台词组成的检索矩阵。
2. **按平台发现**：默认依次搜索 SkillHub、ClawHub、GitHub、Hugging Face Spaces；搜索页、市场卡片和精选列表只作发现入口。
3. **建立原始候选池**：只记录发现事实和收集时 8 个字段，不在发现阶段宣称正式准入。
4. **去重与回溯上游**：按原始项目、规范地址、固定版本、Skill 入口和实质功能去重；镜像、fork、搬运和多平台条目回溯到 canonical source。
5. **执行排除与准入**：先查硬性/软性排除，再检查四项准入条件。
6. **执行只读核验与安全分级**：阅读说明、清点包内容、审查代码和数据流；未经授权不运行。
7. **分类、评级和降级**：确定唯一主归档、辅助标签、接入难度、准备度、维护状态、质量分和推荐顺序。
8. **形成正式库与内部留痕**：正式推荐项、适配候选、观察项和排除项分开保存；排除项不得混入正式交付。
9. **质量检查与维护**：核对证据、字段、数量、链接和结论边界，并按学期制持续更新。

### 3.1 三层候选状态

| 层级 | 含义 | 能否进入正式推荐 |
|---|---|---|
| 原始候选池 | 已发现，尚未完成准入与核验 | 否 |
| 内部观察/适配池 | 有参考价值，但存在软性排除、许可证待确认、停更、仅实验、仅方法参考或 SB-A 适配要求 | 否；完成缺陷修复和重新核验后再判定 |
| 正式库 | 四项准入全部满足，安全和许可证门槛通过，证据可追溯，至少达到“全部通过（未实测）” | 是 |

### 3.2 产品交付三级展示（方案B）

为避免把“正式入库门槛”错误地同时当成“候选展示门槛”，产品交付采用“正式推荐、条件候选、需适配候选”三级展示，正式准入门槛不变：

| 展示层级 | 定义 | 产品表述边界 |
|---|---|---|
| 正式推荐 | 已通过现行正式准入、安全、许可证、固定版本和来源追溯门槛 | 可表述为已通过项目静态准入；未经授权实测的，不得表述为已实际运行 |
| 条件候选 | 专业相关、来源可追溯且未发现禁止性风险，但仍有许可证、维护、版本稳定性或境外服务依赖等条件 | 可以展示，不得写成可直接安装、部署或正式入库 |
| 需适配候选 | 工作流、模板、代码或方法可支撑专业任务，但必须本地化、替换接口、补专业模板或剥离高风险步骤 | 必须标注“需适配后使用”，并列出具体改造动作 |

每个专业类最低展示 3 个候选，建议目标为 5 个；依次使用正式推荐、条件候选、需适配候选补足。若不足 3 个，必须记录检索范围和真实缺口，不得用实质不相关项凑数。恶意行为、涉密或军事禁止内容、不可审查二进制、来源完全不可追溯以及实质不相关内容仍不得展示。

专业相关性改用专业任务映射，不依赖名称关键词。候选至少满足“支持核心课程或研究对象、支持常用研究方法、生成明确需要的成果、处理专业特有数据或流程”之一；每项必须写明专业任务、输入、输出、适用理由和使用限制，相关度低于 3/5 不进入展示清单。

零结果或低结果专项补查同时覆盖六类检索词：专业名称及中英文别名、核心课程、典型研究方法、典型工作任务、典型成果与数据对象、常用软件/数据库/分析流程。

全局去重继续生效：同一 Skill 在 GitHub、SkillHub、ClawHub、Hugging Face Spaces 等来源重复出现时，只保存一个规范条目和同一稳定 ID，其他平台作为来源别名；一个 Skill 可以被多个专业类引用，但数据库只存一次，各专业类报告不得重复计入产品总数。

## 4. 平台发现规则

### 4.1 默认固定顺序

当用户没有限定来源时，依次执行：

1. **SkillHub**：优先补充中文社区、本土创作者、中文说明和境内使用线索；按命名空间、slug 和版本固定条目，读取实际包文件并回溯上游。平台安全报告、verified、评分和下载量不得替代本项目核验。
2. **ClawHub**：优先发现文本型、Prompt 型和人文社科类 Skill；检查实际 Skill 内容、发布者和可追溯上游，不因市场评分直接信任。
3. **GitHub**：发现 Skill、MCP 工具、脚本型工作流和适配资源；正式证据落到具体入口、目录树、关键脚本、依赖、许可证和固定提交。
4. **Hugging Face Spaces**：发现交互式 Demo、Gradio/Streamlit 应用和学科原型；检查代码仓库、模型/API 依赖、数据上传路径和境内可达性。

固定顺序用于保证覆盖，不表示三个平台的候选可以用同一证据标准。用户明确限定平台时允许缩小范围，但必须在启动记录中说明，不能把限定范围写成“已完成全平台调研”。经用户批准扩展到其他公开平台时，仍须执行同等的上游回溯、固定版本、许可证和安全门槛。

### 4.2 平台风险关注点

- Skill 市场或镜像：防止恶意搬运、来源伪装、缺失文件和市场卡片夸大功能。
- SkillHub：区分 ClawHub 同步项与社区上传项；检查命名空间、版本、文件哈希、平台中文翻译与原文差异、上游地址和包内许可证。社区上传但无可确认许可证的项目只留内部观察。
- GitHub/MCP：检查身份验证、权限范围、网络端点、安装命令、未锁依赖和外部写入。
- Hugging Face Spaces：检查外部 API、模型自动下载、数据上传、GPU/内存要求和中国高校网络可达性。
- 平台的下载量、Star、Like 和更新时间只作为排序证据；它们会变化，必须记录核验日期，不能替代内容核验。

## 5. 学科门类优先级

| 优先级 | 判定条件 | 覆盖门类 |
|---|---|---|
| ★★★ 最高 | 工具密集度高、开源生态成熟、专业数量多 | 理学（07）、工学（08）、医学（10） |
| ★★☆ 高 | 数据/API 丰富、Skill 数量多，专业数适中 | 经济学（02）、法学（03）、文学（05）、管理学（12） |
| ★☆☆ 常规 | 专业数少或专用工具少，可按门类集中收集 | 哲学（01）、教育学（04）、历史学（06）、农学（09）、艺术学（13） |
| 不纳入 | 涉及军事学及相应敏感范围 | 军事学（11） |

优先级只决定收集顺序，不降低任何门类的准入质量。用户可指定某一期先处理其他门类；来源框架中“第一期法学、哲学、艺术学”属于批次安排，不改变上述长期等级。

## 6. 跨学科复用度

| 级别 | 判定标准 | 收集顺序 |
|---|---|---|
| 通用 | 对所有学科普遍适用，如论文写作、文献管理、数据可视化、文档处理 | 最高，先于学科专有项 |
| 跨门类 | 覆盖 3 个及以上学科门类 | 高 |
| 门类内 | 覆盖 1–2 个学科门类或一个门类内多个专业 | 正常 |
| 专业专有 | 仅服务一个专业方向 | 需求驱动 |

复用度影响搜索和推荐顺序，不改变主分类。每项 Skill 仍必须只有一个主归档位置，其他适用范围使用辅助标签表达。

### 6.1 适用人员

适用人员可多选，但必须依据候选实际任务和权限填写，不能仅因“高校通用”而全选：

| 人员 | 典型场景 |
|---|---|
| 学生 | 课程作业、实验操作、论文写作、自学复习 |
| 教学人员 | 课堂演示、教案设计、课件制作、测验和批改辅助 |
| 科研人员 | 文献检索、数据分析、实验模拟、论文投稿 |
| 行政人员 | 文档处理、数据统计、流程管理、报告生成 |

涉及作业、成绩、个人信息、未公开论文、审稿材料或校内系统写入时，适用人员标签不等于授权；仍须执行数据、权限和人工复核边界。

## 7. 筛选规则

### 7.1 硬性排除

命中任一项即停止正式准入，写入内部排除记录并保留证据：

1. 纯娱乐、角色扮演或游戏陪玩，且无明确教学、科研或高校工作用途。
2. 军事学相关，包括军事战略、武器装备、军事情报或其他本项目禁止范围。
3. 依赖涉密数据库、受控敏感数据且没有可执行的脱敏与授权方案。
4. 发现恶意代码、挖矿、秘密窃取、数据外传、破坏、提权、持久化或绕过授权行为。
5. 把 `curl | bash`、对用户输入执行 `eval()/exec()`、未审远程载荷下载后执行等高风险行为作为不可剥离默认流程。
6. 原始链接返回 404/403 或无法访问，且找不到可信镜像或可追溯上游。
7. 关键载荷为来源不明或无法审查的二进制，无法确认其行为与来源。

### 7.2 软性排除与观察

以下候选不直接进入正式库，转入内部观察/适配池：

| 类型 | 判定 | 处理 |
|---|---|---|
| 已废弃 | 最近更新超过 18 个月，且社区关注度低（如 GitHub Star 少于 10）并无其他维护证据 | 标记废弃，不主动推荐，寻找替代项 |
| 仅概念描述 | 只有博客或想法，没有具体 Skill、代码、模板或完整工作流 | 写入需求缺口清单 |
| 仅供实验 | 发布者明确声明不可用于生产或仅为实验原型 | 只供技术参考，不推荐给普通师生 |
| 无许可证声明 | 能研究其公开内容，但没有明确使用和修改授权 | 仅内部调研，不进入正式可部署或可修改清单 |

### 7.3 准入四条件

候选必须全部满足以下条件，才进入正式核验和入库判定：

1. **说明完整**：存在 `SKILL.md`、README 或等价说明，含不少于约 200 字的实质性任务描述，并能确认目标、输入、输出和主要步骤。
2. **前提明确且可获得**：列出依赖、API Key、运行环境、账号、数据源和权限；正式部署所需依赖必须能在中国高校合规、稳定地取得，不能取得时转适配池。
3. **许可证允许**：固定版本的许可允许本项目拟议的教学、科研、复制和改造方式；用途超出许可或禁止修改时不得正式准入。
4. **来源可追溯**：有完整、可访问的原始仓库或正式发布地址，能定位 canonical source 和审查版本。

## 8. 安全等级

| 等级 | 基准定义 | 结论 |
|---|---|---|
| SA · 低风险 | 纯文本 Skill；不执行代码、不发起网络请求、不读写本地文件 | 可进入正式评估；部署仍须校内制度和内容复核 |
| SB · 中风险 | 只读 API、指定目录内受控读写或范围明确的系统命令；行为和权限可审查 | 限制使用；需隔离目录、域名白名单、最小权限和操作日志 |
| SB-A · 高风险适配候选 | 原包包含自动下载模型/依赖、不可控脚本、动态执行、`curl | bash`、未锁远程执行或其他可分离高风险步骤 | 原包不得直接安装；仅在剥离风险步骤、重写脚本、固定依赖/哈希并人工复核后重新评估 |
| X · 禁止 | 军事/涉密禁止范围、恶意行为、来源不明二进制、关键内容不可审查或风险无法限制 | 排除，不进入正式库 |

- 现有项目的历史 `SC`、`SX` 记录保留原值以维持追溯；条目按本流程复核时统一映射为 `X`，并保留原具体原因。
- 详细检查继续使用 `SECURITY_REVIEW_PROTOCOL.md`；若其旧分级口径与本节冲突，以本节为准。
- 安全通过只表示在已读取固定版本中未发现阻断问题，不等于运行环境绝对安全。

## 9. 核验流程与状态

### 9.1 四步核验

| 步骤 | 名称 | 操作 | 输出 |
|---|---|---|---|
| ① | 说明核验 | 阅读 README、SKILL.md、依赖声明和许可证，不安装不运行 | 说明核验记录 |
| ② | 包内容核验 | 列出全部文件，标出可执行文件、配置、硬编码密钥、远程载荷和缺失引用，不安装不运行 | 包内容核验记录 |
| ③ | 干运行核验 | 阅读核心代码并在纸面/静态层面梳理数据流、权限、外部依赖和中国高校可达性；“干运行”不等于执行代码 | 接入难度、安全结论和质量评分 |
| ④ | 小范围实测 | 仅在用户明确授权后，于隔离、无真实凭据、无校内敏感数据且可回滚的环境验证典型场景 | 实测报告 |

### 9.2 状态枚举

- `待核验`：只完成发现和收集时字段。
- `前两步通过`：说明与包内容已核验。
- `全部通过（未实测）`：完成静态干运行核验，尚未执行候选。
- `全部通过（已实测）`：完成用户授权的小范围实测。
- `核验驳回`：任一步发现不可接受问题。

不得把“说明已核验”“包内容已核验”“全部通过（未实测）”表述为已经安装、成功运行或证明有效。

### 9.3 正式入库最低核验深度

- `待核验` 和仅完成说明核验的候选只留原始候选池。
- 完成说明与包内容核验、尚未完成静态干运行的候选最多进入内部观察池；不得给出正式安全等级或进入正式库。
- 正式库最低状态为 `全部通过（未实测）`：必须完成说明核验、包内容核验和静态干运行核验，并据此形成正式安全等级、接入难度、许可证和依赖结论。
- `全部通过（已实测）` 不是正式入库的默认必要条件；实测仍须用户明确授权。
- 用户可要求更高核验深度，但不得把正式库门槛降低到本节以下。若当轮只获准较浅核验，应缩小交付结论为候选发现或观察清单，不能称为正式库。

## 11. 接入难度、准备度和 API 可达性

### 11.1 接入难度

| 等级 | 名称 | 判定 | 预计工作量 |
|---|---|---|---|
| A | 调整少 | 纯文本、无代码/外部依赖，或只需改路径变量 | 不超过 0.5 天 |
| B | 少量调整 | 申请 API Key、替换数据源地址或修改配置，核心逻辑不变 | 0.5–2 天 |
| C | 较多调整 | 改写核心流程、替换不可访问服务或增加本地化模块 | 2–5 天 |
| D | 仅参考 | 核心依赖在校内不可用，或架构无法兼容 | 不部署，只参考方法 |

工作量是调研估计，不是实施承诺；必须记录估计依据。

### 11.2 准备度

| 等级 | 判定 |
|---|---|
| 可直接使用 | 接入难度 A、安全等级 SA、网络可达，无需修改即可使用 |
| 微调试可用 | 接入难度 A/B、安全等级 SA/SB，只需配置、申请 Key 或替换镜像源，预计 2 天内完成 |
| 需适配开发 | 接入难度 C、安全等级 SB 或 SB-A，需要重写、替换服务或本地化；SB-A 原包仍不得直接部署 |

### 11.3 API 依赖可达性

| 级别 | 判定 | 处理 |
|---|---|---|
| 无需 API | 不发起外部网络请求 | 无额外网络依赖 |
| 境内可访问 | 国内或 CARSI 等合规渠道可稳定访问 | 记录访问和账号条件 |
| 需 VPN | 境外服务，校内只有经批准网络路径可访问 | 明示限制，并提供替代方案 |
| 不可访问 | 中国境内无可用服务路径 | 转适配池，寻找国内替代 API |
| 需替换 | 服务终止或不接受新用户 | 寻找等效服务，不进入直接使用队列 |

可达性是时点事实，每次复核必须记录日期和证据。

### 11.4 外部 API、本地软件与本地接口的强制分离

依赖核验必须把以下三类事实分别判断、分别记录，禁止合并成“需要 API/外部服务”一个结论：

| 类别 | 判定边界 | 记录要求 |
|---|---|---|
| 外部联网/API 调用 | 候选固定包或其不可省略的核心流程会向远程服务端点发起网络请求，或必须使用远程托管服务 | 记录“是/否”、服务名或端点、发送数据、认证条件、境内可达性和固定版本证据 |
| 本地专业软件或运行时依赖 | 需要用户已经安装并获授权的 Abaqus、ANSYS、MATLAB、CAD、数据库、编译器或其他本地环境 | 记录“无/可选/实操时需要”，以及用途、版本和许可条件；不得写入外部 API 字段 |
| 本地脚本/插件接口 | 使用本机软件提供的 Python 接口、SDK、COM、CLI、插件接口或本地 ODB/文件接口 | 记录“不使用/按需使用/必须使用”和对应实操场景；本地接口不等同于远程 API |

填写结论必须以固定版本包内的实际行为为准，不得仅因出现软件名、SDK、Python 接口、插件接口或“API”字样，就推断候选会进行外部 API 调用。文档链接、能力说明、可选工具清单和未来可扩展接口也不能单独作为“需要 API”的证据。

- 纯说明、清单、模板或审查型 Skill 如无可执行载荷、无网络请求且无不可省略的远程服务，外部联网/API 调用必须填“否”。
- Skill 本身不调用接口，但用户在后续模型自动化、结果读取或插件执行中可能使用本地接口时，外部联网/API 仍填“否”，本地脚本/插件接口填“按需使用”并说明触发场景。
- 专业软件只是多个可选求解器之一时，本地专业软件依赖填“可选”，不得把其中任一软件写成强制 API 依赖。
- API 依赖标记为“需要”时，联网行为不得为“无”；必须同时给出实际端点或服务、数据流和固定版本证据。两字段矛盾时不得交付，必须退回复核。
- “需要；Abaqus”“需要；MATLAB”等只写产品名、没有远程请求证据的值为不合格填写；应改记到本地专业软件或本地脚本/插件接口字段。

本节适用于所有新增、补查和被重新核验的条目；既有成果只在条目更新时迁移，不据此自动批量回写。

## 12. 更新活跃度与质量评分

### 12.1 更新活跃度

| 状态 | 最近更新 | 处理 |
|---|---|---|
| 活跃 | 不超过 6 个月 | 质量加分候选 |
| 正常 | 超过 6 个月且不超过 12 个月 | 不加不减 |
| 停滞 | 超过 12 个月且不超过 18 个月 | 标注关注，不进优先队列 |
| 废弃 | 超过 18 个月 | 新候选转观察；已入库项标记废弃并寻找替代 |

若项目成熟稳定、已完成功能且维护方式不依赖频繁提交，可以用发布记录、问题响应和生态兼容性作为反证，但必须写明理由，不得只凭主观判断改成“活跃”。

### 12.2 质量评分

只有四项准入条件全部满足后才取得基础 1 分。每满足一项加分条件加 1 分，最终按 `min(5, 1 + 加分项数量)` 计算，避免来源框架中“基础 1 分 + 5 个加分项”超过满分的歧义。

加分项：

1. 有中文说明、中文界面或可靠中文输出支持。
2. 最近 6 个月有维护更新。
3. 社区活跃度达到参考阈值：GitHub Star ≥ 50、SkillHub 下载 ≥ 100、ClawHub 下载 ≥ 100 或 Hugging Face Spaces Like ≥ 20；必须记录核验日期。
4. 文档包含明确教学、科研或高校工作场景案例。
5. 来自 OpenAI、Anthropic、Microsoft 等官方来源，或可核验的高校、科研机构和权威组织。

| 分数 | 名称 | 处理顺序 |
|---:|---|---|
| 5 | 金牌 Skill | 首批评估与部署候选 |
| 4 | 优质 Skill | 第二批 |
| 3 | 标准 Skill | 第三批 |
| 2 | 可用 Skill | 按需进入候选队列 |
| 1 | 待观察 | 留在内部观察区 |
| 0 | 不纳库 | 排除 |

评分只用于排序，不能抵消安全、许可证、来源或准入门槛。

## 13. 分类和归档规则

### 13.1 唯一主分类

主归档依据 Skill 最核心、最稳定的使用对象和主要输出确定。每项 Skill 只有一个主分类代码；跨学科用途、其他功能、适用人员和原生生态均使用辅助标签表达，不重复计数。

### 13.2 一级分类：学科门类

`01 哲学`、`02 经济学`、`03 法学`、`04 教育学`、`05 文学`、`06 历史学`、`07 理学`、`08 工学`、`09 农学`、`10 医学`、`12 管理学`、`13 艺术学`、`99 跨学科通用`。

- `11 军事学`不纳入公开收集。
- 服务所有或多个门类且没有单一学科主对象的通用 Skill 归入 `99`。
- 有明确学科主对象的 Skill 归入相应门类，即使方法本身可跨学科复用。
- 现有 01–06 功能分类继续作为历史主分类和今后辅助功能标签保留，不批量改写既有编号。

### 13.3 二级分类：功能子类

- 编码格式：`门类代码-两位序号`，如 `07-03`、`99-01`。
- 子类名称原则上不超过 8 个汉字，描述该学科中的具体任务或主要产出。
- 新建子类前先检索同门类既有子类，避免同义重复。
- 同一 Skill 的主子类由主要输出决定，其他能力写入辅助功能标签。

### 13.4 三级分类：Skill 文件

- Skill 条目使用来源平台的原始名称或原始 ID 命名，并保留稳定内部 ID。
- 文件名冲突时追加来源平台或稳定短 ID，不覆盖同名条目。
- 原始事实、派生分类和项目判断分开保存，分类调整不得改写原始证据。

### 13.5 归档字段：18 个字段

**收集时必填 8 项：**

1. 分类代码
2. 中文名称
3. 原始名称
4. 一句话用途
5. 来源平台
6. 来源地址
7. 适用人员
8. 收集日期

**核验后补充 10 项：**

9. 接入难度
10. 质量评分
11. 关键依赖
12. 许可证
13. 最近更新
14. 核验状态
15. API 依赖标记
16. 安全风险等级
17. 替代方案
18. 备注

既有数据字典要求的 canonical source、固定版本、证据位置、发布者、网络/文件/凭据行为等字段继续作为扩展字段保留；18 项是最低集合，不是字段上限。

来源框架汇总表把第 18 项写为“课程”，详细的“完整集 18 字段”表写为“备注”。本流程以详细字段表为准，保留“备注”为第 18 项；适用课程如对当轮任务重要，作为扩展字段单独记录，不覆盖备注。

## 14. 降级处理

内容有价值但不满足直接使用条件时，不得包装成正式可直接使用项：

| 情况 | 降级处理 | 标签 |
|---|---|---|
| 核心依赖境外 API | 保留结构参考，列出可替换的国内或校内服务 | 需适配 |
| 技术栈与校内环境不兼容 | 提取 Prompt、算法或工作流方法，不安装原包 | 仅参考方法 |
| 需要付费订阅或商业许可 | 记录费用和授权条件，不默认推荐给学生 | 商用许可 |
| 数据源境内不可访问或受限 | 记录 CARSI、经批准 VPN 或替代数据源条件 | 数据受限 |
| 缺少中文支持但功能突出 | 保留候选并建立本地化任务 | 仅英文 |
| SB-A | 列出保留部分、剥离部分、重写要求、固定依赖、网络白名单和人工确认点 | 仅适配后使用 |

## 15. 八步判定链

候选完成发现和去重后，必须依次判定，不可跳步：

1. **排除规则**：命中硬性排除则归档后停止；命中软性排除则转观察/适配池。
2. **准入四条件**：未全部满足，不进入正式核验或正式库。
3. **安全等级**：SA/SB 继续；SB-A 只进入适配池；X 排除。
4. **许可证合规**：只有许可覆盖拟议用途的候选继续；无许可声明只留内部研究。
5. **接入难度**：评定 A/B/C/D，并记录依据。
6. **质量评分**：按 0–5 分计算，不用评分抵消硬门槛。
7. **跨学科复用度**：评定通用/跨门类/门类内/专业专有，作为排序权重。
8. **排序和入库**：在已通过全部门槛的候选中按质量分、复用度、学科优先级和维护状态排序；观察、适配和排除项不得混入正式库。

每个结论必须能回到固定版本文件、公开地址或本地快照；事实、观察和项目判断使用不同措辞。

## 16. 持续更新规则

### 16.1 学期制维护

| 时间 | 操作 |
|---|---|
| 每学期开学前（2 月、8 月） | 对默认平台做全量增量扫描，重点检查近 6 个月新增的教育、学术和高校工作类 Skill |
| 每学期期中（4 月、10 月） | 抽查入库项的源仓库、许可证、依赖、API 和链接状态 |
| 每学期期末（6 月、12 月） | 清理或标记超过 18 个月未更新且质量分不超过 2 的条目，寻找替代方案并收集下学期需求 |

### 16.2 即时触发

| 事件 | 响应 | 目标时限 |
|---|---|---|
| 发现学科核心新工具 | 按完整准入和核验流程优先处理 | 3 个工作日内启动并给出初步结论 |
| 已入库原仓库被删除或归档 | 标记失效/废弃并寻找替代 | 1 个工作日内 |
| 依赖 API 变更或终止 | 评估影响，标记需适配并启动替代调研 | 5 个工作日内 |

紧急需求只压缩排期，不得跳过硬性排除、准入、安全、许可证和来源追溯门槛。实测仍需用户明确授权，不采用来源框架中“跳过干运行直接实测”的高风险做法。

## 17. 每轮完成检查

只有同时满足以下条件，才能声明本轮 Skill 调研完成：

- 已记录范围、角色、来源、时间截点、验证深度和完成判据。
- 已按获准平台完成检索矩阵，并如实说明未覆盖的平台。
- 原始候选、去重结果、正式项、观察/适配项和排除项边界清楚。
- 正式项全部通过四项准入、安全、许可证和来源追溯门槛，核验状态至少达到“全部通过（未实测）”。
- 每项只有一个主归档，跨学科和其他功能使用辅助标签。
- 收集时 8 字段和核验后 10 字段完整；扩展追溯字段按数据字典填写。
- 核验状态没有被夸大为已安装、已运行或已证明有效。
- 正式报告不包含排除项；内部记录保留落选原因和证据。
- 链接、固定版本、许可证、数量和分类统计经过一致性检查。
- 与本流程的任何偏离均已写入决策日志。
