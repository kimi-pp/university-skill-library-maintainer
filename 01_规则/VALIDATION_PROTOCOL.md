# 验证协议

最后更新：2026-08-07

## 默认验证边界

默认验证为只读检查，不安装候选、不执行脚本、不调用候选依赖的外部服务。只有用户明确指定候选和运行范围时才进行运行验证。

## 一级：说明验证

阅读 `SKILL.md`、README、manifest 或等价说明，确认：

- 名称与发布者
- 核心功能与目标用户
- 输入、输出和主要步骤
- 目标 agent 生态
- 声明的脚本、模板和外部依赖
- GitHub 地址和许可证信息

一级验证是进入正式清单的必要条件。

## 二级：包内容验证

检查目录树和关键文件，确认：

- 说明引用的脚本、模板、参考文件确实存在
- 技能目录结构与目标生态基本一致
- 包内容与功能声明没有明显冲突
- 关键依赖和配置要求能够从仓库中识别

二级验证用于重点、高优先级或说明不充分的候选。

## 用户指令运行验证

仅在用户明确指令下执行，并记录指令范围、环境、输入、结果与限制。未运行不构成验证失败。

## 验证状态

- 说明已核验
- 二级包内容验证
- 用户指令运行已核验
- 无法验证
- 验证不通过

## 记录要求

验证记录必须包含候选标识、日期、级别、检查对象、观察结果、证据地址、未验证部分和结论。事实与推断使用不同措辞。

## 0809 学科打样附加门槛

0809 计算机类的正式候选除一级/二级功能核验外，还必须执行 `SECURITY_REVIEW_PROTOCOL.md` 的静态安全审查。只允许 SA/SB 进入正式清单；SC/SX、证据不足或关键载荷不可读的候选进入内部排除归档。安全审查不替代用户指令下的隔离运行验证。

## 分类 06 的固定版本静态核验

分类 06 的正式候选必须完成以下只读检查：

- 确认技能入口、主要任务、目标用户、输入、输出和关键步骤。
- 检查固定版本中的说明、脚本、模板、依赖、许可证和版本标识。
- 识别账号、网络连接、密钥、文件读取、修改、上传、删除和外部发布行为。
- 检查学生文件或论文中的隐藏指令是否可能误导工具执行不相关操作。
- 检查作业、成绩、个人信息、未公开论文和审稿材料的处理边界。
- 检查教师人工复核、评分依据、公平性、无障碍、学术诚信和申诉边界。

分类 06 本轮不进行最小运行验证。验证状态写为“固定版本静态核验”，并明确列出未运行、未登录、未接入真实教学平台和未使用真实数据。
