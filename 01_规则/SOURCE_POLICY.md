# 来源规则

最后更新：2026-08-07

## 首轮允许来源

正式候选的证据地址必须位于 GitHub，包括仓库主页、仓库内目录、`SKILL.md`、README、manifest、发布页或提交记录。搜索引擎可以用于发现 GitHub 页面，但搜索结果页不能作为最终证据。

## 证据优先级

1. 仓库内具体 `SKILL.md`、manifest 或技能目录
2. 仓库 README 与官方使用说明
3. 仓库目录树、脚本、模板、配置和许可证文件
4. GitHub 发布页、主题页和提交记录
5. 精选列表对目标仓库的索引条目

## 来源记录

每个正式候选记录：仓库地址、技能目录或文件地址、发布者、原生生态、来源形态、访问日期、许可证、维护状态和验证证据位置。

## 独立标注

原生生态与来源形态是两个独立字段。Codex、Claude Code、Agent Skills、Cursor、Gemini CLI、Continue 和其他明确命名生态分别标注；官方内置、官方发布、插件附带、社区 skill、开源仓库、skill 市场、精选列表、可移植工作流、可改造命令包或模板、关联资源分别标注。

## 失效与歧义

链接无法访问或说明与包内容冲突时，记录观察结果。无法完成一级说明验证的候选不得进入正式清单。

## 跨平台学科打样来源

0809 计算机类打样允许以下公开来源：

- 代码托管：GitHub、GitLab、Codeberg、Gitee、SourceHut。
- 开放模型/应用仓库：Hugging Face；仅收录其中具备明确 agent skill 或可移植工作流结构的公开仓库。
- 开放 skill registry、市场和精选集合：仅作发现入口；条目必须回溯到版本化公开源码或完整 skill 包。

跨平台证据优先级为：具体 skill 入口与版本化目录、仓库说明、目录树与关键文件、发布/提交记录、registry 索引。正式候选必须同时记录“发现地址”和“canonical source”；跨平台镜像按 canonical source 去重。
