# 三类 GitHub 技能调研实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 GitHub 范围内完成三个高校功能分类的 skill 候选发现、轻量验证、知识库建设，并分别交付三个 Excel 清单和三个 Word 报告。

**Architecture:** 采用“范围记录 → 多路径发现 → 原始池 → 去重与轻量验证 → 分类知识库 → 独立 Excel/Word → 渲染校验”的流水线。每个功能分类拥有独立数据、知识库入口和交付文件；跨分类候选通过稳定内部标识关联，不通过合并报告解决。

**Tech Stack:** Markdown、GitHub 网站与 GitHub API/CLI、JSON/CSV 中间数据、工作区内置 Python、电子表格与 Word 文档生成库、Office/LibreOffice 或内置渲染工具。

## Global Constraints

- 本轮唯一来源平台为 GitHub；搜索入口可以是 GitHub 自身或限定到 GitHub 的搜索，但正式候选地址必须落到 GitHub 仓库、目录、文件或发布页。
- 本轮只调查三个分类：学术写作、引用与出版；文档、表格、演示文稿与办公自动化；文献检索与学术研究。
- 三个分类分别生成独立 Excel 和独立 Word，共六个正式交付文件。
- 落选或排除归档的 skill 只进入内部记录，不进入任何最终 Excel 工作表或 Word 正文、附录。
- 默认验证仅包含说明验证和包内容验证；未收到用户明确指令时，不安装候选、不执行候选脚本、不进行最小运行验证。
- OpenAI Codex、Anthropic Claude Code、Agent Skills 及其他 agent 生态独立标注；来源形态与原生生态使用两个字段记录。
- 原始文件 `D:\高校AI工作台\国内大学本科专业目录.xlsx` 保持不变。
- 当前工作区不是 Git 仓库；不得擅自初始化 Git，计划执行期间以调研日志和决策日志保留变更历史。
- 调研在指定范围内连续两轮补充检索未发现有实质区别的新候选后达到发现饱和。
