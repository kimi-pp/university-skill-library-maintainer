# 高校 AI 技能库调研项目设计

## 1. 文档状态

- 项目名称：高校 AI 技能库调研
- 设计版本：1.2
- 确认日期：2026-08-06
- 当前状态：设计已经用户确认；已完成 GitHub 上五个功能分类，后续每轮范围仍由用户当次任务限定
- 工作区原始资料：`国内大学本科专业目录.xlsx`

## 2. 项目目标

本项目面向高校学生与员工，构建一个可检索、可验证、可持续扩展的 AI agent skill 候选知识库。每轮调研按照用户发布任务时限定的范围发现候选，再通过统一字段、轻量验证、兼容性评级和高校场景映射，形成可供后续选型、适配、安装和内部技能开发使用的基础资料。

本阶段交付两类正式报告：

1. Excel 清单：保存结构化候选数据、来源地址、简要功能、适用角色、兼容等级和验证状态。
2. Word 报告：保存重点 skill 的详细功能、使用场景、依赖、适配建议、局限和验证证据。

同时建立 Markdown 规则库、知识库、验证记录和总索引，以便后续按需读取局部内容，避免每次加载全部调研资料。

## 3. 工作原则

### 3.1 广覆盖、后分层

在用户当次任务指定的范围内，候选不会因为暂时不兼容 Codex、许可证尚不明确、依赖付费服务或存在操作风险而在发现阶段被过早删除。此类问题作为字段和评级记录，在最终推荐阶段处理。

### 3.2 证据优先

每项正式候选必须留下来源地址、访问日期和至少一级验证记录。无法验证的候选可以保留在原始候选池，但不得被描述为已经验证。

### 3.3 轻量验证

本项目只以阅读说明、检查技能包结构和抽查引用资源为默认验证方式，不默认进行安装或最小运行验证。只有用户在具体任务中明确要求运行时，才按照该次指令的对象和边界执行运行验证。

### 3.4 不做过度防御

风险、权限、隐私和外部依赖用于帮助选型，不作为大范围拒收理由。仅对明显恶意、欺诈、伪装载荷和完全无关内容做直接排除。

### 3.5 原始资料不被改写

工作区现有的 `国内大学本科专业目录.xlsx` 保持原样。后续如需建立专业映射，生成独立的派生数据文件，并在知识库中记录派生关系。

### 3.6 每轮范围由用户限定

本设计定义可调研对象的总体边界，不自动触发全范围调查。每次开始新的调研任务时，以用户当次指定的生态、角色、功能、来源、数量、时间或其他约束为实际执行范围。未被当次任务纳入的领域保持未调查状态，不因本设计中的总体分类而自动扩展。

## 4. 调研对象

### 4.1 纳入的技能生态

- OpenAI Codex 官方、内置、插件附带及社区 skills
- Anthropic Claude Code 官方与社区 skills
- Agent Skills 开放标准及兼容技能包
- GitHub、GitLab 等公开代码平台上的开源技能仓库
- 公开 skill 市场、精选列表和技能集合
- Cursor、Gemini CLI、Continue 等生态中具有可移植性的 agent 工作流
- 可以合理改造为 skill 的高质量开源命令包、代理工作流和任务模板
- skill 所引用的 MCP、脚本、模板、数据文件和说明资源

单独的 MCP 服务、普通软件产品、提示词碎片和纯文章不直接作为 skill 收录；如果它们是某个 skill 的依赖或能形成完整可复用工作流，则作为关联资源记录。

上述来源在最终 Excel 和 Word 中必须独立标注，不合并为笼统的“其他来源”。为避免概念混杂，使用两个独立维度：

- 原生生态：OpenAI Codex、Anthropic Claude Code、Agent Skills、Cursor、Gemini CLI、Continue、其他明确命名的 agent 生态
- 来源形态：官方内置、官方发布、插件附带、社区 skill、开源仓库、skill 市场、精选列表、可移植工作流、可改造命令包或模板、关联资源

一个候选可以具有一个主要原生生态和多个来源形态。MCP、脚本、模板、数据文件和说明资源只作为“关联资源”独立标注，不与主体 skill 混为同一条候选。

### 4.2 服务对象

- 学生：本科生、硕士生、博士生、留学生及有无障碍需求的学生
- 教学人员：专任教师、助教、课程负责人和教学管理人员
- 科研人员：教师研究者、博士后、实验室成员和科研管理人员
- 学生支持人员：辅导员、就业人员、招生人员和学生事务人员
- 行政与专业支持人员：行政、财务、人力资源、法务、宣传、图书馆、实验室、信息化和校园运营人员
- 高校管理人员：院系负责人、职能部门负责人和学校管理层

### 4.3 功能分类

1. 学习辅导与知识理解
2. 文献检索与学术研究
3. 学术写作、引用与出版
4. 编程、数学、数据分析与可视化
5. 文档、表格、演示文稿与办公自动化
6. 课程设计、教学材料与教学评估
7. 科研项目、实验、基金与实验室管理
8. 学生事务、就业、心理支持与校园生活
9. 行政审批、会议、知识管理与协作
10. 图书馆与信息素养
11. 信息技术、软件开发与网络安全
12. 招生、宣传、活动与公共沟通
13. 国际化、多语言与无障碍支持
14. 合规、隐私、学术诚信与质量保障

后续可在不破坏一级分类的前提下增加二级标签。新增一级分类需要在决策日志中说明原因。

## 5. 收录规则

### 5.1 初始候选池

满足以下任一条件即可进入初始候选池：

- 能完成高校场景中的一项明确任务
- 包含可复用的流程、指令、脚本或模板
- 可以直接使用，或能够以合理成本适配
- 对本项目后续设计内部 skill 有明显方法价值
- 来源、说明或包内容至少有一项可以访问和检查

### 5.2 正式清单

候选进入正式清单必须同时满足：

- 有稳定或可追溯的来源地址
- 能用一句话说明核心功能
- 已完成至少一级验证
- 已标注适用角色和功能分类
- 已标注兼容等级与验证状态
- 与现有正式条目不是无实质差异的重复项

### 5.3 排除归档

以下候选进入内部排除归档，不从过程记录中删除：

- 与高校学生或员工工作完全无关
- 只有营销页面，且无法找到说明或包内容
- 仅包含零散提示词，不构成可复用工作流
- 明显恶意、欺诈或包含伪装载荷
- 与已收录条目完全重复的镜像或无实质修改分叉

每个排除条目必须记录排除理由、证据地址和判定日期。排除归档只用于内部去重、审计和避免重复调查，不进入最终 Excel 清单或 Word 报告。

## 6. 兼容性评级

- A：Codex 原生可用，可直接安装或按现有格式使用
- B：轻量适配，修改目录、元数据或少量工具调用即可使用
- C：深度适配，核心方法可复用，但需要较多重写
- D：设计参考，不建议直接安装，但工作流或知识结构值得借鉴
- X：排除归档，不进入正式推荐范围

兼容性评级描述技术适配成本，不等同于功能质量、安全等级或推荐优先级。

## 7. 验证协议

### 7.1 一级：说明验证

阅读可获得的 `SKILL.md`、README、manifest、官方说明页或等价资料，确认名称、核心功能、输入输出、声明依赖和目标平台。

### 7.2 二级：包内容验证

检查目录树及关键内容，确认说明中引用的脚本、模板、参考资料和配置文件实际存在；抽查文件内容是否与声明功能一致。

### 7.3 用户指令运行验证

运行验证不属于默认调研流程。只有用户在具体任务中明确指定运行对象和范围时才执行，并单独记录用户指令、运行环境、输入、结果和限制。未收到明确运行指令时，不安装候选、不执行候选脚本，也不把“未运行”视为验证失败。

### 7.4 验证状态

- 说明已核验
- 包内容已核验
- 用户指令运行已核验
- 无法验证
- 验证不通过

每项验证记录包含：候选标识、验证级别、验证日期、检查对象、观察结果、证据位置、未验证部分和验证者说明。

## 8. 调研流程

1. 记录用户当次任务限定的调研范围、输出要求和停止条件。
2. 在当次范围内建立来源清单和检索词矩阵。
3. 按指定生态、功能分类、用户角色或其他条件进行候选发现。
4. 将发现结果写入原始候选池，不在发现阶段进行重度筛除。
5. 规范名称、生态归属、来源形态、功能描述和标签，识别重复、镜像及上下游关系。
6. 对去重后的候选执行一级验证。
7. 对高相关、高复用或高影响候选执行二级验证。
8. 仅在用户明确指令下，对指定候选执行运行验证。
9. 完成兼容性、适用性、成熟度、风险和推荐优先级评级。
10. 按当次任务要求将候选映射到高校角色、工作场景或本科专业类别。
11. 生成或更新 Excel 清单、Word 详细报告及 Markdown 索引。
12. 对链接、字段完整性、任务范围覆盖、文档排版和交付文件可打开性进行质量检查。

## 9. 覆盖与停止条件

总体知识库不设置固定候选数量上限，但每轮调研的实际范围完全由用户当次任务限定。任务开始时必须在过程记录中写明：

- 本轮目标和服务对象
- 纳入与排除的生态或来源
- 纳入的功能分类或具体场景
- 数量、时间、语言、许可证或维护状态等限制
- 要求的验证深度
- 本轮交付形式和完成判据

当用户未指定某个维度时，只能做支持当前任务所需的合理补充，不自动扩展为对十四个功能分类或全部生态的全面调查。本轮调研在用户规定的完成条件满足，或指定范围内连续两轮补充检索未发现有实质区别的新候选时结束。

项目只承诺在每次指定范围、公开可访问来源和当前检索条件下实现系统性覆盖，不声称穷尽互联网中的全部技能。

每个候选使用稳定的内部标识。正式清单至少包含以下字段：

- 来源形态
- 关联资源类型

## 12. 报告设计

### 12.1 Excel 清单

工作簿至少包含：

- `使用说明`：字段解释、筛选方法和版本信息
- `Skill总表`：所有正式候选及核心字段
- `分类统计`：按原生生态、来源形态、功能、角色、兼容性和验证状态汇总
- `来源清单`：各独立生态、来源形态、检索入口、访问日期和本轮覆盖状态

Excel 以筛选、排序和后续补充为目标，不在单元格中堆积过长说明。落选或排除归档的 skill 不进入任何最终交付工作表。

每个功能一级分类必须生成独立的 Excel 工作簿，不把多个功能分类合并为同一工作簿。文件名使用 `序号_功能分类_技能清单.xlsx`。同一 skill 确实适用于多个分类时，可以分别进入相应工作簿，但必须标注其他关联分类和重复关系。

### 12.2 Word 报告

Word 报告包含执行摘要、当次调研范围、调研方法、生态与来源形态说明、分类全景、重点候选详解、适配建议、共性能力缺口、风险与限制、结论和附录。各原生生态与来源形态使用独立标签或独立小节呈现，不合并为笼统的“其他”。重点候选详情按统一模板撰写，避免不同条目之间信息粒度不一致。落选或排除归档的 skill 不进入 Word 正文或附录。

每个功能一级分类必须生成独立的 Word 文档，不把多个功能分类合并为同一报告。文件名使用 `序号_功能分类_调研报告.docx`。总索引可以汇总各分类的文件入口和统计信息，但不得替代各分类的独立交付文件。

### 12.3 首轮任务交付

首轮任务仅检索 GitHub，分别形成以下六个交付文件：

- `01_学术写作引用与出版_技能清单.xlsx`
- `01_学术写作引用与出版_调研报告.docx`
- `02_文档表格演示文稿与办公自动化_技能清单.xlsx`
- `02_文档表格演示文稿与办公自动化_调研报告.docx`
- `03_文献检索与学术研究_技能清单.xlsx`
- `03_文献检索与学术研究_调研报告.docx`

## 13. 质量标准

- 正式候选的来源地址完整率为 100%
- 正式候选的一级验证覆盖率为 100%
- 正式候选的角色、分类、兼容等级和验证状态字段完整率为 100%
- 排除条目的排除理由记录率为 100%
- 最终 Excel 和 Word 中排除归档条目的出现数量为 0
- Excel 与 Word 中使用的候选名称和内部标识一致
- Markdown 总索引中的路径均可定位到对应文件
- 最终 Excel 和 Word 文件均通过打开、内容和版式检查
- 调研报告明确区分事实、验证观察与项目判断

## 14. 项目边界

本阶段不默认安装或运行候选，不批量执行未知脚本，不向外部服务上传校内数据，不代表学校制定正式制度，也不直接构建面向最终用户的完整产品。只有用户在具体任务中明确指定时，才对指定候选进行安装或运行验证。深度安全审计、内部技能开发和系统集成属于后续阶段，需要单独确定优先级和实施计划。

## 15. 变更规则

- 新增来源、二级标签和字段解释可直接记录到过程日志。
- 修改一级分类、验证等级、兼容等级或全局规则，必须记录到决策日志。
- 每次调研任务的实际范围直接采用用户当次指令，并记录到调研日志；它不被视为对全局设计的修改。
- 调研中的事实变化更新知识库和最近核验日期，不回写或掩盖历史验证记录。
- 用户的新要求优先于本设计；发生冲突时，记录变更原因和受影响文件。
