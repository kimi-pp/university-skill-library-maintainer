# 研究生学科与本科专业 Skills 映射 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基于教育部现行目录，生成覆盖全部 883 种本科专业、全部研究生一级学科和专业学位类别的可审计双向相关性映射工作簿，用于 Skills 学科标签与检索。

**Architecture:** 先固定教育部官方来源并解析成两个不可变主数据集；研究生 2025 年文件只作为 2022 版目录与旧目录的对应关系证据，不重复改写已经是现行口径的 2022 版目录。再通过“专业类种子规则＋专业级例外＋关系校验器”生成多对多映射。最终由一个聚合器产生双向索引、零映射台账和质量发现，再使用 `@oai/artifact-tool` 生成一份含来源、规则、统计和复核清单的工作簿。

**Tech Stack:** Windows PowerShell 7、绑定版 Python 3（`pypdf`、标准库）、绑定版 Node.js、`@oai/artifact-tool`、Node `assert` 测试、Git。

## Global Constraints

- 本科端以教育部《普通高等学校本科专业目录（2026年）》为权威来源，必须覆盖 13 个门类、92 个专业类、883 种专业。
- 研究生端以《研究生教育学科专业目录（2022年）》为现行基础目录，并核对截至 2026-08-16 能检索到的教育部、国务院学位委员会正式文件；2025 年《有关学科专业调整对应关系表》用于记录新旧目录沿革，不把旧目录名称反向覆盖到 2022 版现行名称。
- 研究生基础目录完整性基线为 14 个门类、117 个一级学科、67 个专业学位类别；有效目录必须保留目录来源和新旧对应关系。
- 所有代码按文本保存，保留前导零及 `T`、`K` 等后缀。
- 每个本科专业最多一个学术学位主映射和一个专业学位主映射；不存在合适映射时保留零映射状态，不强行填充。
- 关系等级只能是“主映射/核心对应”“其他核心对应”“强相关”“延伸相关”“目录参考”。
- Skills 行为只能是“默认标签”“默认辅助标签”“扩展检索”“跨学科召回”“仅目录查看”“无”。
- 军事学关系只能使用“目录参考＋仅目录查看”，不得进入任何 Skills 标签、检索或推荐字段。
- 两端所有零映射目录项必须保留；“尚未复核”“确认无映射”“军事学限制”不得合并为一个状态。
- 自动规则只产生候选；只有完成规则复核的记录才能标记“已依据规则复核”。
- 输出只作 Skills 标签与检索相关性映射，不得宣称为教育部官方升学、报考或培养对应关系。
- 只使用 `load_workspace_dependencies` 返回的运行时和依赖，不安装系统或仓库第三方包。
- 所有工作簿作者操作使用 `@oai/artifact-tool`；不使用 `openpyxl`、`xlsxwriter` 或 `pandas.ExcelWriter`。
- 第一次生成工作簿前，必须且只能成功运行一次 `mark_artifact_operation_started.mjs --operation-kind create --expected-output-count 1 --output-format xlsx`。
- 最终文件固定保存到 `D:/高校AI工作台/outputs/01a004e5-65dc-7c52-bd8c-7e29e9e058bc/研究生学科与本科专业Skills相关性映射.xlsx`。
- 不修改用户现有 `Skills学科应用方向分类表.xlsx` 和 `国内大学本科专业目录.xlsx`。
- 当前仓库存在大量用户未提交改动；每次提交只暂存本任务明确列出的文件。

- [ ] **Step 3: Implement deterministic PDF/HTML extraction**

Implement these typed functions in `extract_official_catalogs.py`:

- `pdf_text(path: Path) -> str`: extract page-aware text and retain page boundaries for exception reporting.
- `parse_undergraduate(text: str) -> list[dict]`: return normalized undergraduate records plus rejected-line metadata.
- `parse_graduate_base(text: str) -> list[dict]`: return deduplicated academic and professional-degree records.
- `parse_correspondence(html: str) -> list[dict]`: convert official new-directory/old-directory table rows into typed lineage records.
- `enrich_with_correspondence(base: list[dict], correspondence: list[dict]) -> list[dict]`: attach legacy codes and names without changing current 2022 codes or names.
- `write_payload(path: Path, source_ids: list[str], records: list[dict]) -> None`: write sorted UTF-8 JSON with metadata and exceptions.

Parsing rules:

- Normalize full-width spaces and repeated whitespace but never alter codes or names.
- Treat six-character undergraduate codes plus optional `T`/`K` suffix as professional records.
- Forward-fill the latest visible undergraduate category and professional-class headers from the same PDF table block.
- Treat four-digit graduate codes under academic headings as `学术学位一级学科`; treat four-digit professional-degree category codes under professional headings as `专业学位类别`.
- Convert graduate doctoral/master display differences into `degree_levels` without creating duplicate `(object_type, object_code)` records.
- Parse new-to-old correspondence rows as rename, move, merge, or split lineage; the 2022-side code and name always remain authoritative in `graduate_effective.json`.
- Reject any correspondence row whose 2022-side code/name conflicts with the 2022 PDF instead of silently changing the effective catalog.
- Reject a record when its required code/name cannot be parsed; write the rejected raw line and page into an exception list in the corresponding payload rather than guessing.
