# 高校专业 Skill 库文件化自动维护工作流设计

日期：2026-08-27

状态：用户已批准

适用项目：`D:\高校AI工作台\高校AI技能库调研`

## 1. 目标

把现有 Skill 调研、筛选、打分、去重、版本复核和 Word/Excel 交付流程制作成可部署到其他 Windows 机器的 Codex 自动工作流。

工作流按可配置的执行频率和启动时间运行，检查：

1. 教育部现行公开本科专业目录中 13 个非军事学门类的新增或变化；
2. 各专业类或相应专业范围内四个指定社区的新 Skill；
3. `99 跨学科通用`范围的新通用 Skill；
4. 已收录 Skill 的新版本、来源失效、许可证、依赖和维护状态变化；
5. 新发现与既有条目的跨平台重复关系。

通过正式准入的新增或更新项可以自动纳入主台账；条件候选和需适配候选只进入查验报告，不自动升级为正式推荐。每轮输出中文 Word 查验报告和 Excel 查验表；只有受影响的专业类才重新生成专业类 Word/Excel。

## 2. 已批准的产品决策

- 部署平台：Windows 单机单写者。
- 执行引擎：Codex 自动任务，采用高质量单模型和高推理强度。
- 专业范围：现行公开 13 个非军事学门类；军事学不纳入。
- 通用范围：`99 跨学科通用`。
- 来源顺序：SkillHub、ClawHub、GitHub、Hugging Face Spaces。
- 自动准入：只有正式推荐项可以自动纳入；条件候选和需适配候选进入人工查验清单。
- 通知：只有发现变化或运行失败时通知。
- Office：部署机器保证安装 Microsoft Office。
- 交付刷新：每轮生成一份总 Word、一份总 Excel，并只刷新受影响专业类的 Word/Excel。
- 数据存储：不使用 SQLite、Access、服务端数据库或其他数据库。
- 设置格式：使用 TOML，不使用 XLSX 保存运行设置。

## 3. 规则依据与用户偏离

工作流必须读取并执行：

- `01_规则/SKILL_RESEARCH_WORKFLOW.md`
- `01_规则/SECURITY_REVIEW_PROTOCOL.md`
- `01_规则/DATA_DICTIONARY.md`
- `01_规则/REPORTING_STANDARD.md`

用户明确要求不使用数据库。因此，现行规则中“同一 Skill 数据库只存一次”的实现改为：

> 同一 Skill 在 Excel 主台账中只保存一个规范条目和一个稳定 ID，其他平台只作为来源别名；同一稳定 ID 可以关联多个专业类，但产品总数只计算一次。

这只改变持久化载体，不改变全局去重、安全、许可证、来源追溯、固定版本、专业相关性或正式准入门槛。实施时必须把该偏离写入 `06_过程记录/DECISION_LOG.md`。

## 4. 文件化架构

### 4.1 配置与业务数据分离

`workflow-settings.toml` 只保存运行设置，不保存候选、评分、专业映射或版本历史。它不是数据库，也不是调研交付物。

所有持久化业务数据采用以下形式：

1. `Skills主台账.xlsx`：唯一当前基线；
2. 历次 `Skills主台账_YYYYMMDD_HHMMSS.xlsx`：发布前不可变备份；
3. 每轮中文 Word 查验报告；
4. 每轮中文 Excel 查验表；
5. 受影响专业类的 Word/Excel；
6. 现行项目规则要求保留的来源快照和静态证据文件。

不新增集中式 JSON/JSONL、CSV、SQLite 或其他业务数据仓。运行锁、临时文件和 Office 渲染图片只作为临时技术文件，成功或失败收尾后清理；来源证据仍按现行项目规则保留。

### 4.2 Excel 主台账

`Skills主台账.xlsx` 固定包含：

- `当前Skill`：每个稳定 ID 一行，保存当前有效固定版本及完整正式字段；
- `来源别名`：各平台发现地址、canonical source、镜像、fork、搬运关系和去重依据；
- `专业任务映射`：稳定 ID 与门类、专业类、专业、核心任务、输入、输出、相关度和限制的多对多映射；
- `版本历史`：每次已审版本、版本日期、固定版本地址、内容指纹、结论变化及旧版本保留原因；
- `候选观察`：条件候选和需适配候选的当前状态，不与正式推荐混写；
- `目录基线`：教育部目录标题、发布日期、访问日期、URL、快照哈希和范围差异摘要；
- `来源水位`：四个平台最近完整成功检查时间、分页范围和维护状态核验时间；
- `运行记录`：每轮 run ID、开始/结束时间、配置摘要、覆盖范围、结果、输出路径和失败摘要；
- `字段说明`：字段名称、允许值和规则版本。

Excel 主台账使用表格对象、固定表名和稳定列名，禁止依赖单元格位置推断业务含义。主台账只通过“临时副本生成 → 完整校验 → Office 实际打开复读 → 原子替换”更新，失败时保留旧台账。

### 4.3 目录结构

建议新增：

```text
自动维护工作流/
├─ workflow-settings.toml
├─ templates/
│  ├─ daily-report.docx
│  └─ daily-review.xlsx
├─ ledger/
│  ├─ Skills主台账.xlsx
│  └─ archive/
├─ output/
│  └─ YYYY-MM-DD/
│     └─ <run-id>/
│        ├─ Skill库自动查验报告.docx
│        ├─ Skill库自动查验表.xlsx
│        └─ 受影响专业类/
└─ runtime/
   └─ 临时工作目录（每轮结束清理）
```

正式专业类交付仍按项目现行 `05_交付物` 结构发布；上面的 `output` 保存该轮查验包和受影响专业类副本。

## 5. TOML 运行设置

### 5.1 设置文件

```toml
config_version = 1

[workflow]
enabled = true
timezone = "Asia/Shanghai"

[schedule]
mode = "weekly"
start_time = "22:00"
weekdays = ["Monday", "Wednesday", "Friday"]
interval_days = 1
day_of_month = 1

[research]
incremental_search = true
full_recheck_interval_days = 7
check_existing_skill_updates = true
include_generic_skills = true

[delivery]
generate_word = true
generate_excel = true
only_refresh_affected_classes = true
notify_on_no_change = false
```

### 5.2 调度语义

`schedule.mode` 允许：

- `daily`：每天在 `start_time` 执行；
- `weekly`：在 `weekdays` 指定星期的 `start_time` 执行；
- `interval`：每隔 `interval_days` 天执行；
- `monthly`：每月 `day_of_month` 日执行；
- `manual`：关闭自动执行，只允许人工启动。

无关字段仍保留但不参与当前模式计算。例如 `mode=weekly` 时忽略 `interval_days` 和 `day_of_month`。

配置验证必须拒绝：未知字段、重复键、无效时区、非法时间、空星期列表、间隔小于 1、日期不在 1–28，以及互相矛盾的设置。限定 1–28 可以避免不同月份没有对应日期时产生隐式补偿。

### 5.3 修改和应用设置

可通过记事本直接编辑 TOML，也提供一个中文“修改运行设置”表单。表单只编辑白名单字段，保存前显示自然语言预览，例如：

> 已启用；每周一、三、五 22:00（Asia/Shanghai）运行；每 7 天执行一次全量复核。

`apply-settings` 操作负责：

1. 解析并严格验证 TOML；
2. 显示即将应用的频率和启动时间；
3. 创建或更新 Codex 自动任务；
4. 将配置文件绝对路径和配置 SHA-256 写入自动任务说明；
5. 读取自动任务配置进行回验；
6. 只有回验一致才报告设置生效。

直接编辑 TOML 后必须执行一次“应用设置”。若自动任务记录的配置哈希与当前 TOML 不一致，任务只报告“设置尚未应用”，不得按旧频率启动调研。

## 6. 可部署 Codex Skill

创建 `university-skill-library-maintainer` Skill，提供以下用户入口：

- `setup`：检查 Windows、Office、Codex、项目路径和四个平台访问条件，创建模板与空主台账；
- `import-existing`：只读导入现有 Word/Excel，建立初始主台账和去重基线；
- `doctor`：检查设置、Office、台账、目录快照、来源连接和输出目录；
- `edit-settings`：打开中文设置表单；
- `apply-settings`：同步 TOML 与 Codex 自动任务；
- `run-now`：人工启动一轮完整流程，但仍执行全部规则和锁；
- `scheduled-run`：仅供已配置的 Codex 自动任务调用；
- `status`：说明下一次计划时间、最近运行结果和最近交付路径；
- `repair-ledger`：从最近通过验证的 Excel 台账备份恢复，不自动覆盖当前文件；
- `rebuild-report`：只从已提交主台账重新生成 Word/Excel，不联网。

部署包不得硬编码用户名、盘符、Python、Node、Office 或缓存路径。所有运行依赖从当前工作区和 Codex 提供的打包依赖中发现。

## 7. 每轮执行流程

### 7.1 启动与基线

1. 读取并验证 `workflow-settings.toml`；
2. 确认本次自动任务使用的配置哈希与当前设置一致；
3. 取得项目级单写者锁；已有运行时安全退出，不启动第二轮；
4. 用 Office 实际打开 `Skills主台账.xlsx` 并复读关键表；
5. 验证稳定 ID、canonical source、固定版本、表头和必填字段；
6. 生成 run ID，并在临时副本中追加“运行中”记录，正式台账此时不变。

### 7.2 专业目录复核

每次运行先核对教育部当前公开目录地址、发布通知和本地快照。公开内容未变化时复用已验证快照并更新核验日期；发现目录标题、发布日期、文件哈希或公开地址变化时：

1. 暂停专业发现；
2. 下载并保存新快照；
3. 对门类、专业类、专业代码和名称逐项生成差异；
4. 更新专业范围和搜索矩阵；
5. 在查验报告中单列目录变化。

范围为现行非军事学 13 门类。可使用专业类的门类按专业类执行；交叉学科无统一专业类代码时按现行专业逐项执行。`99 跨学科通用`独立执行。

### 7.3 新增发现

依次检查 SkillHub、ClawHub、GitHub、Hugging Face Spaces。每个专业范围使用六类检索词：

1. 专业名称和中英文别名；
2. 核心课程；
3. 典型研究方法；
4. 典型工作任务；
5. 典型成果和数据对象；
6. 常用软件、数据库和分析流程。

日常运行优先检查来源水位之后的新记录；达到 `full_recheck_interval_days` 时执行一次完整对账。某个平台失败时继续检查其余平台，并在报告中明确覆盖降级；不得把部分覆盖表述为四平台全量完成。

### 7.4 已有 Skill 版本复核

对 `当前Skill` 和 `候选观察` 中每个规范条目检查：

- canonical source 是否仍可访问；
- 是否出现新 tag、release、提交或平台版本；
- 许可证是否变化；
- 核心说明、依赖、网络端点、权限和文件行为是否变化；
- 维护状态是否跨越 6、12 或 18 个月阈值。

发现新版本后按新候选相同的静态流程重新核验。新版本未通过时保留旧固定版本，并在查验报告中说明“发现新版本但未升级”及原因，不自动删除旧项。

### 7.5 全局去重

去重顺序：

1. canonical source；
2. 原始项目和发布者；
3. Skill 入口路径；
4. 固定版本内容指纹；
5. 实质功能、输入和输出；
6. 镜像、fork、搬运和跨平台别名关系。

同一 Skill 只更新一个稳定 ID；来源差异写入 `来源别名`。同一 Skill 可以关联多个专业范围，但产品总数只计一次。若自动判定不能证明是否重复，则进入人工查验清单，不自动合并。

### 7.6 筛选、核验与打分

按项目权威工作流依次执行：硬性/软性排除、准入四条件、只读说明核验、包内容核验、静态干运行、安全等级、许可证、专业任务相关性、接入难度、准备度、维护状态和质量评分。

关键边界：

- 不安装、不执行候选，不调用候选自己的外部服务；
- 正式推荐最低达到“全部通过（未实测）”；
- 专业相关度低于 3/5 不展示；
- Skill 名称不必包含专业关键词，但必须映射专业核心任务、方法、成果或数据流程；
- 外部远程 API、本地专业软件、本地脚本/插件接口分别记录；
- Abaqus、MATLAB 等本地软件或本地接口不得误写成外部 API；
- 军事、涉密、恶意、不可审查载荷和实质无关项不得展示；
- 条件候选和需适配候选不得表述为可直接安装、部署或正式入库。

### 7.7 准入与发布

自动处理规则：

- 正式推荐新增：写入临时主台账；
- 正式推荐版本升级：追加版本历史并更新当前版本；
- 条件候选：写入 `候选观察` 和查验报告，不进入正式推荐；
- 需适配候选：写入 `候选观察`，列出具体改造动作；
- 排除项：只进入内部排除证据，不进入正式 Word/Excel；
- 无法确定去重、安全、许可证或专业映射：进入人工复核，不自动准入。

全部校验通过后：

1. 备份当前主台账；
2. 原子发布新主台账；
3. 原子发布本轮 Word/Excel；
4. 原子刷新受影响专业类 Word/Excel；
5. 写入最终运行记录。

任一关键校验失败时，旧台账和既有专业类交付保持不变。

## 8. 每轮交付

### 8.1 Word 查验报告

中文 Word 固定包含：

1. 本轮执行摘要；
2. 专业目录变化；
3. 四平台覆盖情况；
4. 新增正式推荐；
5. 已有 Skill 版本更新；
6. 发现新版本但未升级；
7. 条件候选；
8. 需适配候选；
9. 全局去重和来源别名；
10. 受影响专业类；
11. 排除原因汇总（不列排除项名称）；
12. 失败、覆盖降级和人工复核事项；
13. 核验边界和未运行声明。

### 8.2 Excel 查验表

Excel 固定包含：

- `使用说明`
- `执行概览`
- `目录变化`
- `新增正式推荐`
- `版本更新`
- `发现更新未升级`
- `条件候选`
- `需适配候选`
- `去重与来源别名`
- `受影响专业类`
- `排除原因汇总`
- `来源请求审计`

Excel 不包含排除项名称，也不把条件候选和需适配候选计入正式推荐数量。

### 8.3 专业类交付

只对以下情况刷新专业类 Word/Excel：

- 新增或删除正式推荐；
- 正式推荐版本变化；
- 正式结论、安全、许可证、依赖或专业任务映射变化；
- 教育部目录导致范围变化。

只增加来源别名而不改变规范条目时，不重新生成所有专业类文件，只在总查验报告记录。

## 9. Word/Excel 质量门

### 9.1 Excel

- 使用可移植的项目依赖，不出现用户目录或全局缓存硬编码；
- 每个规定工作表存在且名称唯一；
- 表格对象范围覆盖全部数据，不固定到第 500 行；
- 冻结窗格、筛选、换行、列宽、超链接和日期格式正确；
- 公式和统计覆盖全部实际数据行；
- ZIP/OOXML 结构通过校验；
- 使用 Microsoft Excel 实际打开、复读关键表和关键单元格；
- 关闭并重新打开后数据仍非空；
- Word、Excel、主台账中的稳定 ID 和数量一致。

### 9.2 Word

- 中文为主，英文原名、软件名、URL 和许可证保留；
- 用途、适用人员、输入、输出、限制和专业映射使用中文；
- 使用 Microsoft Word 实际打开并导出 PDF 或逐页图像；
- 逐页检查标题、目录、表格、分页、空白页、孤行和超出页边界；
- 文档 SHA 与逐页渲染证据绑定；
- 未完成视觉验证时不得发布正式报告。

## 10. 失败与恢复

- 单个平台不可用：处理其余平台，标记覆盖降级；不伪称全平台完成。
- 全部来源不可用：生成失败查验报告，不更新主台账。
- Excel 主台账损坏：从最近通过 Office 复读的备份提出恢复方案，不自动覆盖损坏文件。
- Office 验证失败：不发布 Word/Excel，不覆盖现有成果。
- 自动任务重复启动：后启动者安全退出。
- 运行中断：删除临时文件，保留旧主台账和既有交付；下轮从已发布水位重新检查。
- 正式发布只允许单写者、同目录临时文件和原子替换；不得先覆盖正式文件再做验证。

## 11. 通知规则

只有以下情况通知：

- 新增正式推荐；
- 正式版本升级；
- 正式项失效、降级或许可证/安全结论变化；
- 教育部目录变化；
- 需要人工决定的条件候选、适配候选或疑似重复；
- 运行失败或来源覆盖显著下降。

完全无变化且执行成功时只归档 Word/Excel，不弹出通知。

## 12. 验收标准

### 12.1 配置和调度

- TOML 五种模式均能生成正确的自然语言预览和 Codex 自动任务计划；
- 未知键、非法时间、非法时区和矛盾字段均被拒绝；
- 修改设置但未应用时不会误按旧计划启动调研；
- `manual` 模式不产生自动联网任务；
- 在另一台 Windows 机器上不改源码即可重新设置项目路径和计划。

### 12.2 文件化状态

- 不创建或依赖任何数据库；
- 新安装可以从现有 Word/Excel 建立初始主台账；
- 相同输入重复执行不新增重复行、不改变稳定 ID；
- 主台账损坏时旧备份仍可用；
- 同一 Skill 跨四个平台只形成一个规范条目；
- 同一稳定 ID 可映射多个专业类但产品总数只计一次。

### 12.3 研究流程

- 现行目录变化可以逐项识别；
- 六类查询词覆盖名称不含专业关键词的相关 Skill；
- 新版本必须重新过安全、许可证、依赖和专业映射门；
- 新版本失败时保留旧版本；
- 外部 API、本地软件和本地接口不会混写；
- 军事学和硬性排除项不会进入产品展示。

### 12.4 交付

- Word、Excel、主台账数量和稳定 ID 一致；
- Excel 在 Microsoft Excel 中实际打开且内容非空；
- Word 在 Microsoft Word 中实际打开、渲染并逐页通过；
- 只刷新受影响专业类；
- 任一关键验证失败时正式文件不变。

## 13. 明确不做

- 不建立数据库或后台管理网站；
- 不把 TOML 当作候选数据仓；
- 不自动安装、执行或实测候选 Skill；
- 不自动把条件候选或需适配候选升级为正式推荐；
- 不纳入军事学或武器相关范围；
- 不因最低展示数量要求而用实质无关候选凑数；
- 不全量重写未受影响的历史专业类交付；
- 不在配置未应用或 Office 验证失败时发布结果。
