# 课程设计、教学材料与教学评估全网技能调研设计

**设计日期：** 2026-08-08

**适用大分类：** 06 课程设计、教学材料与教学评估

**设计状态：** 已完成口头方案确认，等待书面设计复核

**调研范围：** 全网可公开访问的来源，包括但不限于 GitHub

**运行验证：** 本轮不运行候选技能；仅在用户另行明确指令后运行
**文字标准：** 面向没有计算机背景的教师、助教、教学管理人员和学生，以通俗中文解释功能、限制和风险

## 1. 目标

本轮调研为高校学生及员工辅助系统寻找能够支持课程设计、教学材料制作和教学评价的公开技能，并把合格结果整理成可查、可比较、可追溯的技能库。

具体目标如下：

1. 按“大分类 → 小分类”两级结构完成系统检索。
2. 把作业批改、课程论文与毕业论文评阅、期刊与会议论文同行评审纳入本大分类。
3. 对每个正式候选进行固定版本的说明阅读、文件检查、许可证核对和静态安全审查。
4. 只把通过收录门槛的技能写入正式表格和文档；落选项、重复项和安全不合格项仅留内部记录。
5. 为大分类和每个小分类分别交付独立的 Excel 与 Word 文件。
6. 保留来源、版本、许可证、核验日期和安全结论，使后续复查能够找到同一份材料。

## 2. 不在本轮范围内的工作

1. 不安装、不执行候选技能，不登录候选网站，不向外部服务上传真实学生作业、成绩、个人信息或未公开论文。
2. 不把市场宣传页、搜索结果摘要或无法查看完整内容的页面作为正式功能证据。
3. 不把普通软件、单一提示词或泛化模板仅因“与教学有关”就直接认定为成熟技能。
4. 不替教师自动作出最终成绩、学位结论、论文录用或拒稿决定。
5. 不修改其他大分类的现有交付物，不覆盖其他任务正在使用的文件。

### 3.3 唯一主分类规则

每个正式技能只能有一个主要小分类。主要分类依据该技能最核心、最稳定的输出确定，而不是依据它“也能做什么”确定。

例如：

- 主要生成试题，归入 06-05；即使附带评分标准，也只把 06-07 记为辅助标签。
- 主要批改作业并给学生反馈，归入 06-06；如果还能统计班级错题，把 06-08 记为辅助标签。
- 主要设计评分标准表，归入 06-07；即使它可用于论文评分，也不改归 06-11。
- 主要评阅学生论文，归入 06-11；主要评审投稿论文，归入 06-12。

交叉能力写入“辅助功能标签”，不重复计入另一小分类的正式技能数量。

## 4. 来源范围与证据要求

### 4.1 公开发现范围

检索覆盖公开可访问的来源，包括：

- GitHub、GitLab、Gitee、Codeberg、SourceHut 等公开代码托管平台；
- Hugging Face 等公开模型和应用社区；
- 可公开浏览并能取得完整技能包的技能目录或开放市场；
- 高校、教育机构、教学技术组织和开源社区的公开项目页面；
- 可追溯到公开版本文件的其他开放来源。

搜索结果页、推荐榜单和市场卡片可以帮助发现候选，但不能单独证明候选的真实功能和安全性。

### 4.2 正式证据层级

正式结论优先使用以下证据：

1. 原作者或维护组织发布的固定版本源文件；
2. 固定版本中的技能说明、任务步骤、输入输出说明、脚本、模板和依赖清单；
3. 固定版本许可证与发布记录；
4. 与该固定版本直接对应的官方说明页面。

如果同一技能存在多个镜像或转载，只保留可确认的原始上游来源为正式来源，其他页面只作为发现记录。

### 4.3 可收录的候选形式

候选可以是：

- 已按 Agent Skills、Claude Code、Codex 或其他公开技能格式封装的技能；
- 包含明确入口、步骤、输入、输出和配套文件的公开智能体工作流；
- 能够合理改造成技能的高质量开源教学命令包、任务流程或模板组合。

需要改造的候选必须明确标记“需适配后使用”，不能写成可直接使用。

### 4.4 不进入正式交付的情况

以下内容只留内部记录，不进入正式 Excel 和 Word：

- 与本轮十二个小分类无实质关系；
- 只有宣传描述，无法查看技能内容或固定版本；
- 找不到可接受的许可证或使用授权依据；
- 与已收录技能实质重复且没有明显新增能力；
- 主要功能过于薄弱，不能形成可复用的完整工作流程；
- 需要不合理权限、存在明显恶意行为或无法控制的高风险外传；
- 安全等级为 SC 或 SX；
- 来源、版本或作者关系无法可靠确认。

## 5. 核验方式

### 5.1 本轮核验深度

本轮只做静态核验，即阅读和检查候选的公开固定版本内容，不执行候选技能。

每个正式候选至少检查：

1. 它从哪里开始使用，面向什么任务；
2. 需要用户提供哪些材料；
3. 会产生哪些结果；
4. 是否包含脚本、外部工具、模板、数据文件和自动操作；
5. 需要哪些权限、账号、网络连接或密钥；
6. 会读取、修改、上传、删除或覆盖哪些内容；
7. 是否可能把作业、成绩、个人信息、论文或评审意见发送给外部网站；
8. 是否有明确许可证；
9. 固定版本和核验日期是否可追溯；
10. 说明文字与实际文件是否相符。

报告必须把“已阅读固定版本并完成静态检查”与“已经实际运行成功”明确区分。本轮不能出现暗示运行成功的表述。

### 5.2 不运行原则

本轮不进行最小运行验证，不安装依赖，不输入真实数据。只有用户在后续任务中明确指定某个候选并批准运行范围后，才可按该指令另行验证。

## 6. 教育场景安全审查

### 6.1 共同安全闸门

正式候选必须逐项检查以下问题：

- 学生作业、成绩、学号、联系方式等个人信息是否会被上传或转发；
- 未公开论文、审稿材料、教师评语和评审人身份是否会泄露；
- 学生提交的文件或论文中的隐藏指令是否可能误导工具执行不相关操作；
- 工具是否会绕过教师确认，自动把成绩写回教学平台或发布最终评价；
- 工具是否能够说明评分依据，保留教师可复核的证据；
- 评分规则是否可能造成不公平差异，是否允许教师修改和学生申诉；
- 输出是否照顾残障学生、不同语言背景和不同学习条件；
- 功能是否可能鼓励代写、伪造反馈或其他学术不端；
- 工具是否请求与任务无关的高权限、长期密钥或广泛文件访问。

### 6.2 作业、考试和成绩

- 自动评分只能作为教师辅助，必须保留人工复核和修改入口。
- 评分标准、扣分理由和证据应能被教师理解和追查。
- 不允许在没有教师确认的情况下自动发布成绩或覆盖原成绩。
- 真实学生数据默认不上传到无法确认数据处理方式的外部服务。

### 6.3 课程论文与毕业论文评阅

- 工具只能提供检查和意见草稿，不能替代导师、答辩委员会或学校作出学位决定。
- 未公开论文、学生身份和评阅意见必须按敏感材料处理。
- 需要把文字质量问题、研究方法问题、学术规范问题和可能的学术不端线索分开说明。
- 对学术不端只能提示风险和证据位置，不能仅凭自动判断直接定性。

### 6.4 期刊与会议论文同行评审

- 保护稿件内容、作者身份、评审人身份、审稿意见和编辑通信。
- 双盲或单盲评审中的身份规则必须得到尊重。
- 工具只能辅助整理核查点和审稿意见，不能自动作出录用或拒稿决定。
- 如果候选依赖外部网站处理稿件，必须明确说明“会把未公开稿件发送到外部网站”及其风险。

### 6.5 安全等级与收录规则

| 等级 | 通俗含义 | 正式收录规则 |
|---|---|---|
| SA | 未发现会阻止高校试用的明显风险，仍需按说明使用 | 可收录 |
| SB | 有可管理的限制，例如需要人工复核或避免输入真实敏感材料 | 可收录，并明确限制 |
| SB-A | 原版有明显风险，但可以通过限制权限、关闭上传或增加人工确认等方式改造成可控版本 | 只收录适配方案，不把原版写成可直接使用 |
| SC | 存在不适合当前高校场景的重大风险，或缺少必要控制 | 不进入正式交付 |
| SX | 发现恶意、欺骗、严重越权或不可接受的数据风险 | 不进入正式交付，并保留内部证据 |

## 7. 检索覆盖与停止条件

调研以十二个小分类为覆盖框架。每个小分类至少从以下四类路径检索：

1. 代码托管平台；
2. 技能目录或开放市场；
3. 教育机构、教学技术组织或高校公开项目；
4. 通用搜索发现的其他可追溯公开来源。

完成首轮检索后进行补充检索。当连续两轮补充检索都没有发现功能上有实质新增、且能够通过正式收录门槛的候选时，该小分类达到本轮停止条件。

停止条件不等于“全网不存在其他技能”。报告必须把结论限定为截至核验日期、在本设计覆盖的公开来源和关键词范围内发现的结果。

## 8. 数据组织与编号

### 8.1 技能编号

正式技能使用与平台无关的统一编号：

`FD-06-0001`、`FD-06-0002`，依次递增。

编号不因来源平台或小分类改变。技能的主要小分类单独记录。

### 8.2 正式记录的核心字段

面向普通用户的字段放在前面：

- 技能编号；
- 技能名称；
- 主要小分类；
- 它能帮您做什么；
- 适合谁；
- 什么时候值得使用；
- 需要您提供什么；
- 会交付什么结果；
- 使用前要注意什么；
- 是否涉及作业、成绩、论文或个人信息；
- 使用难度：可直接使用、需要少量调整、需要重新改造；
- 安全等级和通俗说明；
- 本轮核验深度。

用于追溯的字段放在后面：

- 原始来源；
- 固定版本；
- 核验日期；
- 许可证；
- 作者或维护组织；
- 辅助功能标签；
- 涉及的脚本、外部网站、账号、网络、密钥、读写或上传行为；
- 详细安全证据；
- 适配要求；
- 来源证据文件位置。

## 9. 通俗语言标准

所有正式 Excel、Word 和知识库摘要都遵守以下规则：

1. 让没有计算机背景的教师、助教、教学管理人员和学生能够直接理解。
2. 先说“能解决什么问题、适合谁、会得到什么”，再给版本和技术追溯信息。
3. 专业词第一次出现时使用中文解释。例如：
   - rubric 写成“评分标准表”；
   - LMS write-back 写成“自动把成绩写回教学平台”；
   - prompt injection 写成“学生文件中的隐藏指令可能误导工具”；
   - dependency 写成“运行时还需要安装的其他软件”。
4. 不在用户说明区使用没有解释的 API、MCP、流水线、代理、数据结构等词语。
5. 使用难度统一写成“可直接使用”“需要少量调整”“需要重新改造”。
6. 安全风险必须写成具体后果，例如“会把学生作业发送到外部网站”，不只写“存在数据风险”。
7. Word 使用短句和短段落；英文名称、许可证、版本号和原始地址集中放在追溯信息区。
8. 通俗化不能删掉或改写来源、版本、许可证和安全证据的准确含义。
9. 交付前检查空白占位词、未解释缩写和暗示“已运行成功”的文字。

2. **AI技能清单**：列出该文件范围内的全部正式技能；
3. **分类统计**：统计技能数量、安全等级、使用难度和主要来源；
4. **来源清单**：列出原始来源、固定版本、许可证和核验日期。

大分类 Excel 包含本轮所有正式技能，并为每项填写唯一主要小分类。小分类 Excel 只包含该小分类的正式技能，不复制其他小分类条目。

### 10.4 大分类 Word 结构

大分类 Word 按以下顺序编写：

1. 这类工具解决什么问题；
2. 适合哪些人；
3. 十二个小分类导航与数量；
4. 怎样选择；
5. 共同使用条件；
6. 共同限制与教育安全闸门；
7. 本次核验深度；
8. 来源与结论边界。

### 10.5 小分类 Word 结构

每个小分类 Word 先解释该小分类的用途和选择方法，再逐项介绍正式技能。每项技能按以下顺序说明：

1. 它能帮您做什么；
2. 适合谁；
3. 什么时候值得使用；
4. 需要您提供什么；
5. 会交付什么结果；
6. 使用限制；
7. 作业、成绩、论文和个人信息安全；
8. 接入难度与适配要求；
9. 本轮核验深度；
10. 固定版本、许可证和原始来源。

## 11. 知识库、规则和内部记录

### 11.1 知识库

知识库使用 Markdown，并镜像“大分类 → 小分类 → 技能”的结构。至少包含：

- 大分类入口索引；
- 十二个小分类入口索引；
- 每个正式技能的详细记录；
- 固定版本来源快照索引；
- 安全审查记录；
- 许可证与版本证据；
- 交付文件索引。

主入口必须能通过链接直接进入每个小分类和正式技能，避免后续重复读取全部材料。

### 11.2 规则更新

执行阶段需要把以下已批准规则写入项目规则文件：

- 本轮范围由用户限定为全网公开来源；
- 每个大分类和小分类分别制作独立 Excel 与 Word；
- 每个技能只能有一个主要小分类；
- 落选项不进入正式表格和文档；
- 默认不做运行验证；
- 正式文字必须适合非计算机背景用户；
- 作业批改、学生论文评阅和正式同行评审使用不同的小分类和安全边界。

### 11.3 内部记录

落选候选、重复项、安全不合格项、搜索词和补充检索轮次放在内部过程记录中。内部记录用于解释覆盖范围和决策过程，不属于 26 份正式交付文件。

## 12. 质量检查

### 12.1 内容检查

- 十二个小分类全部完成检索并记录停止条件；
- 每个正式技能只有一个主要小分类；
- 正式条目都能找到固定版本、许可证和来源证据；
- 静态核验结论与实际阅读的文件一致；
- SB-A 条目只描述适配后方案；
- SC、SX、重复项和落选项没有进入正式交付；
- 没有把作者辅助写作和正式评审混为一类；
- 没有把课程论文评阅与期刊、会议同行评审混为一类。

### 12.2 安全检查

- 逐项说明是否接触作业、成绩、个人信息、未公开论文和评审材料；
- 逐项说明是否连接外部网站以及会发送什么；
- 逐项检查教师人工复核、评分证据、申诉、公平性和无障碍问题；
- 不出现自动发布成绩、自动作学位决定或自动录用拒稿的推荐；
- 不把静态检查写成已成功运行。

### 12.3 通俗化检查

- 删除空白占位词和不完整句子；
- 首次出现的专业词有通俗中文解释；
- 功能、输入、输出、限制和风险都使用可直接理解的表述；
- 用户说明区不堆放技术缩写；
- 来源、版本、许可证和安全证据保持准确。

### 12.4 文件检查

- 13 个 Excel 均有四个规定工作表；
- 13 个 Word 均按规定结构生成；
- Excel 的筛选、排序、列宽、换行和链接可正常使用；
- Word 的标题、目录、分页、表格和链接可正常阅读；
- 所有 Excel 与 Word 都经过实际渲染检查；
- 大分类与小分类数量相互一致；
- 知识库索引中的链接有效。

## 13. 异常处理

- 来源暂时无法访问：保留内部记录并寻找原始上游或公开存档；无法取得足够证据时不正式收录。
- 版本持续变化：选择核验日期可固定的提交、发布包或存档，并记录版本标识。
- 许可证不清楚：不正式收录，直到获得明确证据。
- 功能跨多个小分类：按主要输出确定唯一主分类，其他能力只记辅助标签。
- 安全证据矛盾：采用更保守的等级，并在内部记录矛盾来源；达不到收录门槛时排除。
- 正式文件生成失败：保留已核验数据，修复后重新生成并再次渲染检查，不能以未检查的文件替代交付。

## 14. 完成标准

满足以下条件才可宣布本轮调研完成：

1. 十二个小分类均完成规定的公开来源检索和两轮无实质新增的停止检查；
2. 所有正式技能通过固定版本静态核验、许可证核对和教育安全审查；
3. 大分类和十二个小分类的 26 个正式文件全部生成并通过内容与版面检查；
4. 知识库、规则文件、来源快照索引、安全记录和交付索引完整；
5. 正式交付中没有落选项、重复项、SC 或 SX 条目；
6. 所有用户说明符合非计算机背景读者的通俗语言要求；
7. 报告明确说明本轮未运行候选技能，以及结论只覆盖核验日期前可访问的公开证据。
