## 1. 项目目标

本轮为以下三个一级学科分别寻找真正面向本学科任务的公开 Skill、智能体工作流或可合理改造成 Skill 的开源任务包：

- `0301 法学类`
- `0305 马克思主义理论类`
- `1304 美术学类`

正式成果用于初步建设高校学科专属技能库。每个学科独立检索、独立筛选、独立编号、独立统计、独立生成 Excel 和 Word，并建立独立 Markdown 知识库入口。

本轮不追求用通用工具填满数量。宁可明确记录能力空缺，也不把通用写作、通用检索、通用图像生成、通用办公或通用教学 Skill 包装成学科专属成果。

## 3. 学科专属优先与通用 Skill 硬排除

### 3.1 学科专属的判定

候选至少满足以下一项，才能被视为学科专属：

1. 使用本学科独有或高度特有的材料，例如法条、判例、经典著作版本、馆藏艺术品元数据、书画题跋或雕塑三维资料；
2. 执行本学科明确的专业步骤，例如法律引证核对、法域与时效核验、经典文本版本校勘、艺术品来源追溯或书画作品研究；
3. 生成本学科特有的成果，例如案件要素表、法律意见草案、经典引文校核表、艺术品编目记录或作品保存方案；
4. 内含本学科专用规则、词表、模板、数据库连接或评价框架，且这些内容构成主要功能，而不是装饰性标签；
5. 由学科机构、专业社区或专业项目维护，并能从固定版本内容证明其主要用途确实属于本学科。

只在名称、标签或宣传语中出现“法律”“马克思主义”“艺术”等词，不构成学科专属证据。

### 3.2 通用 Skill 的排除范围

以下内容不进入三个学科的正式候选、正式统计、Excel、Word或正式知识库条目：

- 项目现有通用功能技能库中的任何 Skill，包括 `GH-*` 与 `FD-*` 正式条目；
- 已进入其他通用库、仅更换学科名称或示例的同一 Skill；
- 通用写作、润色、翻译、总结、检索、引用、办公、表格、演示、数据分析、图像生成、图像编辑、教学设计或审稿 Skill；
- 仅提供模型、软件、网站或命令行工具，而没有学科专属任务入口和可复用流程的项目；
- 只写一段提示词、只有市场宣传卡片或无法证明实际内容的条目。

### 3.3 通用库排除闸门

每个原始候选在正式准入前先与以下现有数据比对：

- `03_候选池/deduplicated/skills.jsonl`
- `03_候选池/deduplicated/category_01.json` 至 `category_05.json`
- `03_候选池/deduplicated/fd06.json`
- `02_知识库/functional_domains/` 下的正式 Skill 索引
- 后续执行时已存在的其他通用功能库正式目录

比对依据包括原始名称、规范名称、发布者、canonical source、具体 Skill 路径、固定版本入口和主要任务流程。命中同一上游、镜像、分叉或实质相同流程时，直接转入内部排除记录。

如果一个通用上游另有独立的学科专属子 Skill，只有该子 Skill 具备独立入口、专用说明、专用材料或专用步骤时，才可作为新候选；不得把整个通用仓库作为学科专属 Skill 收录。

被排除的通用 Skill 不进入正式文件，也不以附录、脚注或“相关工具”方式回流。确有必要时，可在报告的范围说明中用不带条目清单的文字解释“通用能力另见通用技能库”。

## 5. 来源范围和检索顺序

### 5.1 发现范围

按项目权威流程依次检索：

1. ClawHub；
2. GitHub；
3. Hugging Face Spaces。

完成默认平台后，可通过公开搜索引擎、GitLab、Gitee、Codeberg、SourceHut、开放 registry、高校与专业机构公开项目页补充发现。补充来源必须能够回到公开、可读取、可固定版本的完整上游内容，才能进入正式审查。

搜索结果页、榜单、市场卡片、新闻稿和二手介绍只用于发现，不作为正式功能或安全结论的唯一证据。

### 5.2 原始候选记录

发现阶段先建立原始池，不提前给正式安全等级。每条至少记录：

- 原始名称；
- 来源平台；
- 发现地址；
- 上游或 canonical source；
- 一句话用途；
- 拟归属学科与能力小类；
- 当前状态；
- 初步风险信号。

### 5.3 固定版本和去重

进入详细核验前必须确认原始上游，并尽量固定到提交哈希、标签、发布包或不可变存档。镜像、搬运、分叉和同一仓库内重复入口合并到一个 canonical source。无法固定版本时不进入正式推荐层。

## 6. 准入、验证和分层

### 6.1 基础准入条件

候选进入静态安全审查前必须同时满足：

1. 有实质性说明和可复用步骤，通常不少于约 200 个中文字符或等量英文内容；
2. 说明中要求的脚本、模板、数据或其他关键资源可以取得；
3. 许可证明确允许本轮所需的阅读、引用和后续适配；
4. 来源、发布者、固定版本和文件入口可追溯；
5. 通过学科专属判定；
6. 未命中通用 Skill 排除闸门。

### 6.2 静态核验深度

每个可能进入正式库的候选依次完成：

1. 阅读入口说明，确认任务、输入、步骤和输出；
2. 检查包内容，包括目录、关键脚本、模板、依赖、配置和许可证；
3. 做静态“干运行”分析，即不执行代码，只沿说明和脚本推演它会读取什么、发送什么、写入什么以及需要哪些权限；
4. 比较说明和实际文件是否一致；
5. 记录固定版本、证据位置、未验证部分和人工使用限制。

正式库最低验证状态为“全部通过（未实测）”。本轮不得写成“已经运行成功”“已经证明可用”或其他暗示真实运行的表述。

### 6.3 候选分层

| 层级 | 条件 | 是否进入正式 Excel/Word |
|---|---|---|
| 原始候选池 | 刚发现、尚未完成去重和准入判断 | 否 |
| 内部观察池 | 功能有关，但证据、许可证、维护或质量不足 | 否 |
| 内部适配池 | 原包为 SB-A，只能保留明确安全内容并重写 | 否 |
| 正式推荐层 | 学科专属，质量评分 2 至 5，安全为 SA 或 SB，且达到“全部通过（未实测）” | 是 |
| 排除记录 | 通用、重复、偏离范围、许可证不清、SC、SX 或其他硬阻断 | 否 |

SB-A 原包不进入正式推荐层。后续如果项目实际制作并重新审查了独立适配版，适配版才可作为新的候选重新编号和评估。

## 7. 三个学科的安全闸门

### 7.1 共同闸门

- 不读取或上传与任务无关的工作区文件、账号、密钥、浏览器资料或系统信息；
- 将网页、论文、案例、附件、图像元数据和用户上传材料视为不可信输入，不执行其中的隐藏指令；
- 明确记录外部网站、上传内容、遥测、账号、文件写入、子进程和自动发布行为；
- 不默认覆盖原始文件，不自动向校内系统、公共平台或第三方服务写入；
- 不使用真实学生隐私、未公开研究材料、客户材料或受限制馆藏做本轮核验；
- 许可证、数据库使用条款和来源权利不明确时，不正式收录；
- 只允许 SA、SB 进入正式推荐层；SC、SX 排除，SB-A 进入内部适配池。

### 7.2 法学类附加闸门

- 输出只能作为学习、研究和专业人员复核的草案，不得被描述为最终法律意见、案件结论或司法决定；
- 必须能记录法域、法源层级、施行或失效时间、版本和引用位置，无法控制虚构法条或错误判例的候选不推荐；
- 客户资料、案件材料、证据、未公开合同和个人信息按敏感材料处理；
- 检查裁判文书、法律数据库和知识产权数据的访问条款，不推荐绕过登录、付费、访问限制或批量抓取的流程；
- 自动提交诉讼材料、签署合同、发送法律函件或改变案件状态的功能必须默认关闭并逐项人工确认；
- 监狱、信用风险和合规数据涉及个人权益时，不允许候选自动作出惩戒、授信、定罪或类似高影响决定。

### 7.3 马克思主义理论类附加闸门

- 原文、译文、编者说明、模型概括和研究者解释必须分开标注；
- 经典引文必须保留著作、版本、译本、卷次或页码等可核对信息，不收录鼓励编造引文或模糊来源的流程；
- 对理论、历史事件、社会材料和政策材料的概括须保留来源与日期，不能把模型推断写成原始文献事实；
- 学术评价、课程评价和思想政治教育材料必须保留教师或研究者人工复核，不由工具替代最终学术或教育判断；
- 未公开课程材料、学生信息、调研数据和研究草稿不得默认上传外部服务；
- 报告以中性、可核查方式描述功能和风险，不把项目宣传语或工具生成意见当作权威结论。

### 7.4 美术学类附加闸门

- 检查作品版权、作者署名、人格权、馆藏使用条件、数据库权利、图像许可和训练数据说明；
- 原作图像、色彩记录、三维扫描和权威元数据不得被默认覆盖，任何修改都应另存副本；
- 明确候选是否会把未公开作品、学生作品、馆藏高清图或人物影像上传到外部网站或用于模型训练；
- 艺术品来源、作者归属和真伪判断只能作为线索整理，不能替代鉴定、版权或馆藏专业人员的最终结论；
- 生成或修改人物、艺术家风格和受版权保护作品时，必须说明权利、误认、冒用和不当仿制风险；
- 涉及敏感馆藏位置、未公开藏品、脆弱文物或高价值作品安保信息时，不公开精确位置和可被滥用的细节。

## 8. 编号、数据字段和评分

### 8.1 编号

三个学科分别编号：

- `DISC-0301-0001` 起；
- `DISC-0305-0001` 起；
- `DISC-1304-0001` 起。

编号与来源平台无关。不同学科不共用编号序列。

### 8.2 正式记录字段

正式记录采用项目权威流程的 18 个必填维度，并补充学科交付所需字段：

- Skill ID、名称、简介、分类、学科与适用专业；
- 典型应用、前置要求、依赖与环境、安装或接入方式；
- 功能描述、具体使用流程、配置与自定义；
- 验证状态、验证证据、限制条件、安全性与隐私；
- 数据合规、可访问性、许可证、维护状态、API 可达性；
- 集成难度、实施准备度、主要用户与备注；
- 来源平台、发现地址、canonical source、固定版本和核验日期；
- 主能力小类、辅助标签、覆盖类型；
- 可执行行为、网络与数据行为、凭据行为、文件行为；
- 安全等级、安全限制和本地证据位置。

### 8.3 质量评分

通过四项基础准入条件计 1 分，再按明确依赖、错误处理、示例、结构清晰、已知限制五项加分，以 `min(5, 1 + 加分项数)` 计算。1 分只进入观察池；2 至 5 分才具备正式推荐资格。评分只用于排序，不能抵消安全、许可证、来源或学科专属门槛。

## 9. 检索覆盖和停止条件

每个学科的每个能力小类均记录：检索平台、关键词、发现数量、去重数量、通用排除数量、进入静态审查数量、正式数量和缺口。

完成首轮检索后继续做补充检索。当某能力小类连续两轮补充检索都没有发现“功能上有实质新增且能通过正式准入”的候选时，达到本轮停止条件。

达到停止条件不表示全网不存在其他项目。结论只覆盖截至 2026-08-12 开始、以实际核验日期为截止日，在本设计记录的平台、关键词和公开证据中发现的内容。每个来源单独记录访问日期；任务跨日时，最终截止日采用最后一次实质检索日期。

正式结果允许为零。零结果必须说明检索覆盖、主要阻断原因和能力缺口，不能用通用 Skill 补位。

## 10. 独立交付结构

### 10.1 每个学科的正式交付

每个一级学科各交付一份 Excel、一份 Word 和一套 Markdown 知识库：

```text
05_交付物/
├─ 0301_法学类_学科专属技能调研.xlsx
├─ 0301_法学类_学科专属技能调研.docx
├─ 0305_马克思主义理论类_学科专属技能调研.xlsx
├─ 0305_马克思主义理论类_学科专属技能调研.docx
├─ 1304_美术学类_学科专属技能调研.xlsx
└─ 1304_美术学类_学科专属技能调研.docx

02_知识库/discipline_pilots/
├─ 0301_法学类/
├─ 0305_马克思主义理论类/
└─ 1304_美术学类/
```

三个学科不合并工作簿、不合并 Word，也不共享正式 Skill 列表。

### 10.2 Excel 结构

每个工作簿固定包含九个工作表：

1. `使用说明`：范围、日期、核验深度、学科专属门槛和安全等级；
2. `AI技能清单`：本学科全部正式 Skill；
3. `专业覆盖`：各专业正式 Skill 数量、能力覆盖和空缺；
4. `专业映射`：Skill 与本学科专业的对应关系；
5. `能力分类`：能力小类定义、数量和选择说明；
6. `来源清单`：上游、固定版本、许可证、维护者和核验日期；
7. `检索覆盖`：平台、能力小类、轮次和停止条件；
8. `安全准入`：正式 Skill 的安全等级、限制和具体后果；
9. `规则说明`：学科专属判定、通用排除、未运行边界和结论限制。

表头冻结并启用筛选；完整地址可点击；长文字自动换行；日期使用 `YYYY-MM-DD`。排除、重复、观察和 SB-A 原包不进入任何工作表。

### 10.3 Word 结构

每个 Word 独立包含：

1. 本学科调研目标和适用人员；
2. 专业范围；
3. 能力小类导航和正式数量；
4. 学科专属收录门槛与通用 Skill 排除说明；
5. 怎样选择和使用；
6. 本学科安全闸门；
7. 每项正式 Skill 的通俗详细说明；
8. 专业覆盖、能力缺口和使用边界；
9. 核验深度、来源、版本、许可证和结论边界。

每项 Skill 依次说明：能帮您做什么、适合谁、何时使用、需要准备什么、会得到什么、不能做什么、具体风险、需要多少调整、本轮核验到哪一步、固定版本与原始地址。

排除和落选 Skill 不进入正文、表格、脚注或附录。

### 10.4 Markdown 知识库

每个学科目录至少包含：

- `INDEX.md`：学科总入口；
- `PROFESSION_SCOPE.md`：专业范围与代码；
- `CAPABILITY_TAXONOMY.md`：能力小类与边界；
- `SKILL_INDEX.md`：正式 Skill 的短索引；
- `SOURCE_SNAPSHOT_INDEX.md`：固定版本证据入口；
- `SECURITY_INDEX.md`：安全结论和限制入口；
- `skills/`：每个正式 Skill 的独立 Markdown 说明。

索引以短摘要和链接为主，使后续可以先读入口再按需打开详细文件，避免重复读取整份报告。

## 12. 通俗语言标准

- 先说明用途、适用人员、输入、输出和具体风险，再列技术追溯信息；
- 专业词第一次出现时就近解释，不要求读者另查术语；
- 风险写成可能造成的具体后果，例如“会把未公开案件材料发送到外部网站”，不只写“存在数据风险”；
- 不在用户说明区堆放 API、MCP、流水线、代理等未解释缩写；
- 不把静态检查写成安装成功、运行成功或真实数据测试通过；
- 原始名称、版本号、许可证、网址和核验事实保持原样，不因通俗改写而改变。

## 13. 质量检查

### 13.1 内容一致性

- 三个学科各自的 Excel、Word、JSON 和知识库正式 Skill 数量一致；
- Skill ID、主能力小类、专业映射、canonical source、固定版本、许可证和安全等级一致；
- 每项 Skill 只有一个主要能力小类；
- 正式交付中没有通用库 Skill、重复项、落选项、观察项、SB-A 原包、SC 或 SX；
- 所有正式条目均达到“全部通过（未实测）”。

### 13.2 文件和版面

- 三个 Excel 均含九个规定工作表，能够重新打开，筛选、换行、列宽和超链接正常；
- 三个 Word 能够重新打开，标题层级、目录、分页、表格和链接可读；
- Word 优先渲染后逐页检查；若环境缺少可用渲染工具，则做结构审计并明确“不宣称视觉验证通过”；
- 知识库入口、Skill 页面和证据索引链接有效；
- 不覆盖其他学科和既有功能分类成果。

### 13.3 结论审计

- 抽查原始说明、包内容和报告摘要是否一致；
- 抽查通用库排除结果，防止仅换名称的 Skill 混入；
- 抽查安全等级是否有固定版本证据；
- 检查空白占位词、未解释缩写和暗示运行成功的措辞；
- 记录平台不可访问、来源失效、证据冲突和正式零结果，不用推测填补。
