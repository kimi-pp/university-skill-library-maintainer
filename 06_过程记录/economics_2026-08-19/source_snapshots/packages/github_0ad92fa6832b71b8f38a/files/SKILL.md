# 宏观新闻信号

## 目标

把最近的全球金融新闻、宏观经济数据、央行沟通和市场价格转化为可核验的宏观信号报告。报告要优先回答：发生了什么、为什么重要、影响哪些资产、信号持续多久、最大反向风险是什么。

## 使用原则

- 只基于已获取或用户提供的材料下结论。无法核验的数据写 `N/A（未核验）`，不要补全或猜测。
- 使用技能前先确认当前对话或已提供材料中是否已有用户资产布局；若没有，先询问用户资产布局，再生成宏观报告。用户已告知资产布局时，不重复询问。
- 已知用户持有某类资产时，不仅分析该资产本身，还要分析会通过交叉资产关系影响它的关键变量，例如美元、利率/加息预期、能源价格、通胀预期、地缘政治和风险偏好。
- 每个核心事件至少附 1 个来源链接；重大市场方向判断优先使用官方源、交易所/行情 API、央行/统计局公告或主流财经媒体交叉验证。
- 新闻类请求必须先从 `references/news_apis.md` 中选取相关 RSS 订阅源并尝试抓取；只有 RSS 不覆盖、失败、过旧或无法满足用户指定范围时，才使用搜索引擎、网页浏览或其他抓取方式补充。
- 第三方 RSS、Folo、RSSHub 可用于发现线索，但关键事实应尽量回到原文或官方来源确认。
- 明确数据截止时间和时区；用户未指定时，使用当前日期对应的最近 24 小时作为默认窗口。
- 这是投资研究辅助，不给确定性收益承诺，不把信号写成保证性建议。

## 工作流程

### 0. 确认资产布局

在生成或更新宏观报告前，先检查用户是否已经告知资产布局，例如资产类别、区域、比例、重点关注标的、避险/进攻偏好或不可投资范围。

- 若用户已告知资产布局，后续宏观报告尽量贴近该布局，优先分析相关资产和风险敞口，不重复询问。
- 若用户未告知资产布局，先简短询问；用户暂不提供时，使用默认资产范围继续，但在报告中标明“未提供个人资产布局，按通用宏观资产框架分析”。
- 资产布局仅用于调整报告关注重点和风险映射，不用于承诺收益或给出确定性投资建议。

### 0.1 建立交叉资产观察清单

根据用户资产布局，为每类重点持仓建立“直接资产 + 间接驱动因子”的观察清单。报告中若间接驱动因子出现异动，应说明对用户持仓的传导路径和方向。

| 用户持仓/关注资产 | 必看间接驱动因子 | 典型传导表述 |
|-------------------|------------------|--------------|
| 黄金 | 美元指数、实际利率/美债收益率、加息/降息预期、通胀预期、原油、地缘政治、避险情绪 | “美元走强和实际利率上行通常压制黄金；地缘风险升温、通胀预期抬头或实际利率回落通常支撑黄金。若这些因素方向冲突，应写明主导变量和证据强弱。” |
| 原油/能源 | OPEC+ 供给、地缘政治、美元、全球需求、库存、通胀预期 | “油价上涨可能推高通胀预期并影响利率路径，同时通过成本端影响股票和债券。” |
| 美股/A股 | 利率、美元流动性、信用利差、盈利预期、风险偏好、能源成本 | “利率上行通常压缩估值；美元流动性收紧或能源成本上升可能压制风险资产。” |
| 美债/债券 | 央行政策、通胀、就业、财政供给、避险需求 | “加息预期或通胀超预期通常压低债券价格；避险需求和增长降温通常支撑债券。” |
| 外汇/美元 | 利差、央行政策差、风险偏好、贸易/资本流动 | “美元异动会影响以美元计价的大宗商品，并改变非美资产的汇率敞口。” |

交叉资产分析必须避免机械套用相关性。若市场价格没有确认新闻叙事，或多个因子互相抵消，应明确写出“传导不一致/信号冲突”，并给出当前更值得跟踪的主导变量。

### 1. 判定范围

根据用户请求确定：
- 时间窗口：最近 24 小时、今日、每日综述、每周回顾，或用户指定日期范围。
- 未来事件窗口：默认覆盖数据截止日当天起往后 7 个自然日，用于列出会影响当前资产布局的重大事件、日期和关注点。
- 地区：美国、中国、欧盟、日本、新兴市场，或全球。
- 资产：优先贴近用户已告知的资产布局；未提供时覆盖 A股、美股、美债、美元、欧元、黄金、原油/能源、食品/农业等通用资产。
- 报告深度：快讯、单事件分析、综合日报/周报。

### 2. 选择来源

读取 `references/news_apis.md` 来选择 RSS、指数接口和 Yahoo Finance API。不要一次性加载无关外部资料；只读取当前请求需要的来源和资产。

先选择 RSS，再选择官方公告/API，再选择行情接口。搜索引擎只能作为补充发现工具，不能替代 RSS 抓取步骤。

| 场景 | 优先来源 |
|------|----------|
| 央行、政策、统计数据 | 官方公告、央行 RSS、统计局/财政部/能源机构 |
| 一般宏观新闻 | 彭博、CNBC、FT、WSJ、经济学人、联合早报等 RSS 或原文 |
| 市场行情 | CNBC 指数接口经 `scripts/fetch.py` 获取、Yahoo Finance API |
| 股票指数 | Yahoo Finance API，经 `scripts/format.py` 格式化 |

### 3. 获取数据

RSS、指数接口必须使用 `scripts/fetch.py` 获取。对综合宏观报告，至少尝试 3 个与请求相关的 RSS 源；如果用户指定了地区或资产，优先尝试该范围内的 RSS 源。执行时在内部记录每个来源的状态：`成功`、`无最近窗口内容`、`失败`、`跳过及原因`；最终报告不需要输出这份获取记录。

未来 7 天重大事件必须尽量从官方日历、央行/统计机构公告、交易所日历或主流财经媒体日历核验日期；不得凭记忆补全。无法核验的事件日期写 `N/A（未核验）`，并不要把它作为核心方向判断依据。

```bash
python3 scripts/fetch.py "<url>"
```

如果 `scripts/fetch.py` 因网络或站点限制失败，使用可用的浏览/抓取工具读取 RSS URL；仍然无法获取时，对受影响的事实或数据写 `N/A（未获取/未核验）`，必要时在对应段落简短说明失败原因。不要在未尝试 RSS 的情况下直接使用搜索结果生成新闻主线。

Yahoo Finance API 必须使用 `scripts/format.py` 格式化原始响应：

```bash
python3 scripts/format.py "<api_url>"
```

### 4. 解析与分析

- 实体提取：识别资产、经济指标、国家/地区、央行、关键人物和行业。
- 鹰鸽/风险偏好判断：央行沟通判断 Hawkish/Dovish；风险资产和商品判断 Bullish/Bearish。
- 数据比对：涉及经济数据时对比实际值、预期值、前值，并说明偏差方向。
- 市场映射：把事件映射到利率、美元、黄金、原油、股票指数、信用风险和区域市场。
- 交叉资产传导：围绕用户持仓写清“触发因素 -> 传导变量 -> 持仓影响 -> 需要跟踪的确认信号”。例如用户持有黄金时，美元、加息预期、美债实际利率、原油和地缘政治出现异动，都要说明对黄金的可能压力或支撑。
- 逻辑校验：检查是否存在“利好出尽”“情绪过热”“价格未确认新闻叙事”等背离。

### 5. 生成信号

信号级别只使用以下三档，不使用其他名称：

| 级别 | 说明 | 持续时间 |
|------|------|---------|
| **Trend-Setting** | 趋势级，影响未来数周至数月 | 长期 |
| **Sustained** | 持续级，影响未来数天至数周 | 中期 |
| **Flash** | 瞬时冲击，仅当时段有效 | 短期 |

资产方向只使用以下三档：

| 信号 | 含义 |
|------|------|
| 📈 买入 | 预计上涨，适合做多 |
| 📉 卖出 | 预计下跌，适合做空 |
| ➡️ 持有 | 预期震荡，适合观望 |

冲击强度只使用以下四档：

| 强度 | 说明 |
|------|------|
| 极高 | 重大黑天鹅，对市场有决定性影响 |
| 高 | 重要事件，能引发显著市场波动 |
| 中 | 常规事件，可能引发短期波动 |
| 低 | 次要事件，市场影响有限 |

### 6. 输出报告

生成综合报告时，读取 `references/output_format.md` 并按默认精简模板输出；只有用户明确要求深度版，或事件复杂到精简版无法解释清楚时，才展开更多小节。输出前做自检：

- 是否已检查用户资产布局；未提供时是否先询问，并在用户暂不提供时注明按通用宏观资产框架分析。
- 若用户已提供持仓，是否说明了直接资产和关键间接驱动因子的交叉资产传导。
- 是否已将低相关性新闻合并到“其他观察”，避免机械填满模板。
- 是否已列出数据截止日当天起往后 7 个自然日内的重大事件日期、对当前资产布局的影响路径和需要关注的信号；无法核验处是否标记 `N/A（未核验）`。
- 是否已在内部完成 RSS/API/行情获取自检，且新闻请求已先尝试 RSS。
- 是否每个核心事件都有来源链接或明确标记 `未核验`。
- 是否所有行情数值都有数据时间，缺失处是否写为 `N/A`。
- 是否只使用 `Trend-Setting`、`Sustained`、`Flash` 三种信号级别。
- 是否把最大风险提示写成能反驳当前主线判断的具体风险，而不是泛泛提醒。
- 是否避免确定性收益承诺和无法来源支持的价格预测。
