## ① Purpose & When to Use / 用途与使用时机 {#purpose}

Use this 12-slide outline to build a board or investor deck on digitalization progress — quarterly or ad-hoc. It pairs with `tools/07` deliverable "reporting → PPT outline + script".
用这份 12 页大纲搭建面向董事会或投资人的数字化进展汇报——季度或临时。它与 `tools/07`「汇报→PPT 大纲+讲稿」交付形态配套。

> **FDMM level gate / 成熟度闸口**: **FDMM L3 and above** (you need integrated systems + a measured dashboard to report on). Below L3, report informally via `templates/02` actuals and `templates/05` FDMM movement.
> **FDMM 等级闸口**：**FDMM L3 及以上**（需系统集成+可测看板才能汇报）。L3 以下用 `templates/02` 实际数 + `templates/05` FDMM 变化非正式汇报。

> **What good looks like / 好答案长什么样**: every KPI slide shows baseline → current → target; RAG status is honest (red is allowed); ROI realized is compared to promised; asks are explicit and costed.
> **好答案长什么样**：每个 KPI 页显示基线→当前→目标；RAG 状态诚实（可标红）；已实现的 ROI 与承诺对照；诉求明确且有价。

> **Red flag / 红旗**: a deck full of green with zero red, or "users love the app" as a metric → vanity, violates the Honesty red line (Iron Law 10). Cut it.
> **红旗**：全绿无红、或把「用户爱用 App」当指标 → 虚荣指标，违反诚实红线（铁律 10）。删。

## ③ The 12-Slide Outline / 12 页大纲 {#template}

| # | Slide / 页 | Guidance / 指引 |
|---|---|---|
| 1 | Title + reporting period / 标题+报告期 | Date + FDMM level + one-line ask. / 日期+FDMM等级+一句话诉求。 |
| 2 | Executive summary / 执行摘要 | 3 wins, 2 risks, 1 ask — plain language. / 3 胜 2 险 1 求——说人话。 |
| 3 | FDMM movement / FDMM 变化 | L__→__ with evidence per dimension. / 带证据的逐维等级变化。 |
| 4 | KPI dashboard / KPI 看板 | Baseline→current→target, 4–6 KPIs only. / 仅 4–6 个 KPI，基线→当前→目标。 |
| 5 | Initiative RAG status / 举措 RAG | Red/amber/green with owner + slip reason. / 红/黄/绿 + 负责人 + 延误因。 |
| 6 | ROI realized vs promised / ROI 实现 vs 承诺 | Table from `templates/07`; show pessimistic tail honesty. / 取自 `templates/07`；坦诚展示悲观尾。 |
| 7 | Member experience impact / 会员体验影响 | Retention, NPS, complaint rate — real numbers. / 留存、NPS、投诉率——真实数。 |
| 8 | Compliance & incident summary / 合规与事故摘要 | HI-1~HI-8 status; incidents + MTTR. / HI-1~HI-8 状态；事故+修复时长。 |
| 9 | Investment envelope YTD / 年度投资执行 | Spend vs budget from `templates/02`. / 取自 `templates/02` 的支出 vs 预算。 |
| 10 | Risks & mitigations / 风险与缓解 | Top 3 with named owner. / 前三风险带具名负责人。 |
| 11 | Next-quarter asks / 下季诉求 | Costed, tied to horizon map. / 有价，挂钩时区地图。 |
| 12 | Closing & decision required / 收尾与待决 | Exactly what you need the board to approve. / 你需董事会批的确切事项。 |

> **Worked micro-example / 微例**: Slide 6 shows "Churn-AI: promised 4pp, realized 2.5pp (base case), still positive ROI — continuing with scope cut." That honesty builds board trust.
> **微例**：第 6 页写「流失 AI：承诺 4 个点，实现 2.5 个点（基准情景），仍正向 ROI——缩范围续做」。此诚实建立董事会信任。

### Storytelling Do / Don't / 叙事宜忌 {#s-story}

- **DO**: lead with the ask, show red early, use ranges, cite `data/01` baselines. / **宜**：先抛诉求、早亮红灯、用区间、引 `data/01` 基线。
- **DON'T**: vanity metrics ("app downloads"), hide red as amber, single-point hype, blame vendors without a switch plan. / **忌**：虚荣指标（「App 下载量」）、把红藏成黄、单点吹、无切换预案甩锅供应商。

### 3.1 Per-Slide Content Prompts / 每页内容提示 {#s-prompts}

| # | Slide / 页 | What to put / 放什么 | What to AVOID / 避免 |
|---|---|---|---|
| 1 | Title / 标题 | Period + FDMM level + the one ask / 周期+等级+一句话诉求 | Logo-only cover / 只有 logo 的封面 |
| 4 | KPI dashboard / 看板 | 4–6 KPIs, baseline→current→target / 基线→当前→目标 | 20 vanity metrics / 20 个虚荣指标 |
| 6 | ROI realized / ROI 实现 | Promised vs realized, incl. pessimistic / 承诺 vs 实现含悲观 | Only sunny numbers / 只晒好数 |
| 8 | Compliance / 合规 | HI-1~HI-8 status + incidents + MTTR / 红线状态+事故+修复时长 | "All compliant" no evidence / 「全合规」无证据 |
| 11 | Asks / 诉求 | Costed, tied to horizon / 计价、挂时区 | Vague "need more budget" / 含糊「要多点预算」 |

### 3.2 Board Q&A Prep / 董事会问答准备 {#s-qa}

> Prepare answers BEFORE the meeting. A stammering answer on red slides destroys trust more than the red itself.
> 会前备答。在红灯页支吾比红灯本身更毁信任。

| Likely question / 可能提问 | Prepared answer / 备答 |
|---|---|
| "Why is initiative X red?" / 「X 为何红？」 | Root cause + owner + recovery date / 根因+负责人+恢复日 |
| "Is the ROI real?" / 「ROI 真吗？」 | Point to `templates/07` three-scenario / 指 `templates/07` 三情景 |
| "What if vendor fails?" / 「供应商破产呢？」 | Switch plan + data-export tested / 切换预案+导出实测 |
| "Are members safe?" / 「会员安全吗？」 | HI-2/HI-5 status + human redundancy / HI-2/HI-5 状态+人工冗余 |

### 3.3 Deck Build Checklist / 建页清单 {#s-build}

- [ ] Every KPI has a baseline date. / 每 KPI 带基线日期。
- [ ] At least one honest red (or explain why none). / 至少一个诚实红（或解释为何无）。
- [ ] ROI slide cites `templates/07`. / ROI 页引 `templates/07`。
- [ ] Asks are costed in `templates/02` terms. / 诉求按 `templates/02` 计价。
- [ ] Compliance slide covers HI-1~HI-8. / 合规页覆盖 HI-1~HI-8。
- [ ] Report date stamped on title. / 标题标汇报日。

> **Worked micro-example / 微例**: a 12-slide deck for an L3 boutique chain reported "Churn-AI realized 2.5pp vs 4pp promised (base case), continuing with scope cut" on slide 6 — the board approved the next ask because the miss was disclosed, not hidden. / L3 精品连锁的 12 页汇报在第 6 页写「流失 AI 实现 2.5 点 vs 承诺 4 点（基准情景），缩范围续做」——因坦诚未藏，董事会批了下个诉求。

### 3.4 Reporting Cadence / 汇报节奏 {#s-cadence}

| Cadence / 节奏 | Audience / 受众 | Deck scope / 范围 |
|---|---|---|
| Monthly ops / 月度运营 | Owner + duty managers / 老板+店长 | Slides 3–9 only (movement, KPI, RAG, incidents) / 仅 3–9 页 |
| Quarterly / 季度 | Board / 董事会 | Full 12 slides + Q&A prep (§3.2) / 全 12 页+问答 |
| Ad-hoc investor / 临时投资人 | Investors / 投资人 | 1–2, 6, 11 (summary, ROI, asks) / 1–2、6、11 页 |

> A monthly full-board deck wastes the room; a quarterly ops-only note hides strategy. Match scope to cadence. / 月度全董事会 deck 浪费会议；季度只讲运营藏战略。范围配节奏。

### 3.5 Pre-Meeting Run-Through / 会前走查 {#s-runt}

> Rehearse the deck once, alone, with a timer. The goal is not polish — it is to catch a slide you cannot defend.
> 独自带计时器走一遍。不为漂亮——为抓出你辩不了的页。

- [ ] Every red slide has a root-cause sentence ready. / 每红页备好根因句。
- [ ] Slide 6 ROI cites `templates/07` three-scenario. / 第 6 页 ROI 引 `templates/07` 三情景。
- [ ] Slide 11 asks are costed and tied to the horizon map. / 第 11 页诉求计价并挂时区地图。
- [ ] You can say the FDMM level and target in one breath. / 你能一口气说出 FDMM 等级与目标。
- [ ] Report date is on the title slide. / 标题页有汇报日。

> If the run-through takes >20 min for 12 slides, cut content — boards decide in the first 10. / 若 12 页走查超 20 分，删内容——董事会前 10 分钟就定了。

## ④ Common Mistakes / 常见错误 {#mistakes}

- **Vanity metrics as proof** → violates Honesty red line. See `data/21-anti-pattern-library.md` spirit of over-claiming. / 用虚荣指标当证据 → 违反诚实红线。
- **All-green RAG** → signals hiding problems; board loses trust when reality bites. / 全绿 RAG → 掩盖问题； reality 来时信任崩。
- **No costed ask** → board can't decide; deck wastes the room. / 诉求无价 → 董事会无法决策；浪费会议。
- **ROI without pessimistic tail** → violates Iron Law 6 / G6. Use `templates/07`. / ROI 无悲观尾 → 违反铁律 6/G6。用 `templates/07`。
