## #events-vendor-conferences Vendor Conferences Worth Attending / 值得参会的供应商大会

Vendor events are where product roadmaps drop — attend the one or two vendors you actually run on.
供应商大会是产品路线图的发布地——只参加你实际在用的那 1–2 家。

- **🔄 Club-management / membership SaaS summits / 会籍 SaaS 峰会**: Roadmap, integration news, peer cases for your core system. 路线图、集成消息、同行案例。
- **🔄 Payment & membership-tech conferences / 支付与会员科技大会**: Prepaid compliance, QR/wallet trends per market. 预付合规、扫码/钱包趋势。
- **🔄 Hardware & IoT showcases / 硬件与 IoT 展**: Equipment, gate, locker, body-analyzer previews. 器械、闸机、柜、体测仪预览。
- **🔄 AI/martech vendor days / AI 与营销科技日**: Churn AI, CV posture, CAPI, SCRM updates. 流失 AI、CV 体态、CAPI、SCRM 更新。
- Rule / 规则: Only attend vendors you depend on; a summit for a tool you don't use is a day lost. 只参加依赖的供应商；为不用的工具参会即浪费一天。

## #events-monthly-routine Monthly Intel Routine (30 min/month) / 每月情报例行（30 分钟/月）

A zero-basis operator's whole competitive-intel program. Set a calendar reminder; do it the same day each month.
0 基础经营者的全部竞争情报程序。设日历提醒，每月同日执行。

1. **5 min — Scan one newsletter + one WeChat official account / 扫一份通讯 + 一个公众号**: Note 1 trend worth watching. 记下 1 个值得关注的趋势。
2. **5 min — Check 🔄 show/association calendar for the quarter / 查本季 🔄 展会/协会日历**: Any event worth a visit or a free webcast? 有无值得线下或免费直播的？
3. **5 min — Glance one research headline / 扫一条研究标题**: Does it move a benchmark you track in `data/01`? 是否动摇你在 `data/01` 跟踪的基准？
4. **10 min — Ask or answer ONE thing in a community / 在社群问或答一件事**: Operator knowledge compounds. 经营者知识会复利。
5. **5 min — Log it / 记录**: One line in a notebook: "this month I learned ____; next month I'll check ____." 笔记写一行：「本月学到____；下月查____。」

That's it — consistency beats intensity. Skip the 30-min month and the radar goes dark.
就这么简单——持续胜过载量。漏掉这 30 分钟，雷达就黑了。

### #events-pick-which How to Pick Which to Attend / 如何选参会

A zero-basis operator has maybe 2–3 event days a year. Spend them where ROI is clearest.
0 基础经营者每年约 2–3 个参会日，花在 ROI 最清晰处。

- **Attend if / 参会若**: you're choosing a core system this year (go to that vendor's summit); a free webcast covers a topic you track; a local show has a peer-operator panel. 今年在选核心系统（去该供应商峰会）；免费直播覆盖你跟踪的主题；本地展有同行面板。
- **Skip if / 跳过若**: it's far and paid but you already run the stack; the agenda is all keynotes, no operator cases; you can't name one question to answer there. 又远又收费但你已用该栈；议程全是主旨无案例；你说不出要去答的一个问题。
- **Free first / 先免费**: Most value now streams as webcasts and recaps — watch the recording, keep the day. 多数价值现已以直播与复盘流出——看录像，留白天。

### #events-vendor-redflags Vendor-Pitch Red Flags at Shows / 展会上供应商话术红旗

Shows are where vendors pitch hard. These flags protect you (Iron Law 8 vendor neutrality).
展会是供应商强力推销处。这些红旗保护你（铁律 8 供应商中立）。

- "We're the only one who does X" / 「只有我们能做 X」: false for any mature feature — ask for 2 alternatives. 任何成熟功能都不唯一——要两个替代。
- "No need to export, you'll never leave" / 「无需导出，你不会走」: data-lock trap; walk away. 数据锁定陷阱，走人。
- "Starting price" hides per-seat/per-club add-ons / 「起步价」藏按席/按店加价: demand the all-in number for YOUR size. 要你规模的全包价。
- "Compliant in all markets" unqualified / 无保留说「全市场合规」: compliance is per-market; ask which article (HI-1/HI-3). 合规按市场，问哪条（HI-1/HI-3）。
- "AI does it automatically" with no human-in-loop / 「AI 自动完成」无人在回路: for health/safety/price, insist on oversight (HI-2/HI-6/HI-7). 健康/安全/定价须有人回路（HI-2/HI-6/HI-7）。

除非改变一个决策，否则参会即浪费。带这些回家，而非只拎个袋子。

### #events-glossary Event Jargon Plain / 展会行话说人话

- **Expo vs summit / 展 vs 峰会**: expo = booths to walk; summit = talks to sit. 展=逛摊；峰会=听讲。
- **Keynote / 主旨**: Big-stage vendor vision — inspiring, low on how-to. 大舞台愿景——振奋但少操作。
- **Breakout / 分组**: Small room, often real operator cases — the useful part. 小间常为真案例——有用部分。
- **B2B vs B2C / 企业对企业 vs 对消费者**: Club-tech shows are B2B; consumer fitness festivals are B2C — different crowd. 场馆科技展是 B2B；消费健身节是 B2C，人群不同。
- **Roadmap / 路线图**: Vendor's future feature plan — a promise, verify before you buy on it. 供应商未来功能计划——承诺，购买前核验。

### #events-signal-noise Signal vs Noise Scorecard / 信号与噪声记分卡

When you read an intel item, score it before acting. One "yes" = worth a look; zero = skip.
读到情报条目先打分再行动。一个「是」即值得看；零则跳过。

- Does it affect a system I run or will choose this year? / 是否影响我今年在跑或要选的系统？
- Does it change a benchmark or rule I track? / 是否改变我跟踪的基准或规则？
- Can I act on it in ≤30 days with ≤small effort? / 能否 ≤30 天、≤小投入行动？
- Does it help the member's experience or safety? / 是否利于会员体验或安全？

Three or four yes = put it on the monthly log; one or none = let it pass. 三四个「是」即记入月志；一或零则放过。

> **G13 tri-perspective note / 三视角注记**: Architect — treat industry intel as the input layer for your 3-year roadmap (SKILL.md L5) and for FDMM level decisions; track signals, not noise. Operator — the 30-min monthly routine is your whole program; protect that slot. Member — trends you act on (tech, safety, pricing) eventually reach the member's experience, so filter intel by "does this make the member's club better?" not just "is it shiny?"
> **G13 三视角注记**：架构师——将行业情报视为三年路线图（SKILL.md L5）与 FDMM 等级决策的输入层，追信号而非噪声。运营者——每月 30 分钟例行即你全部程序，守住这个时段。会员——你采纳的趋势（技术、安全、定价）终将抵达会员体验，故以「是否让会员的场馆更好」而非「是否新颖」过滤情报。
