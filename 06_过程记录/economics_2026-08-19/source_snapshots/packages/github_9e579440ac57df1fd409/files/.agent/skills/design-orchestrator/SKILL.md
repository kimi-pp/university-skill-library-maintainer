# Design Orchestrator - 前端设计大师

智能编排型前端设计系统，能够根据场景动态平衡创意和规范，调用 `frontend-design` 和 `ui-ux-pro-max` 两个子 skill，输出生产级代码和完整设计文档。

## 核心能力

- **智能场景分析**：自动识别项目类型、设计关键词、行业特征
- **三条设计路线**：纯创意、纯规范、混合模式
- **交互式选择**：展示每条路线的优缺点，让用户做出明智选择
- **动态平衡**：根据场景自动调整创意和规范的权重
- **完整交付物**：代码 + 设计说明 + 决策日志 + 规范检查清单

## 快速开始

```bash
# 基本用法（推荐）
帮我设计一个 [项目描述]

# 指定路线
用 [路线1/路线2/路线3] 设计一个 [项目描述]

# 调整权重
用混合路线设计 [项目描述]，创意权重 70%
```

## 三条设计路线

### 路线1：纯创意路线（frontend-design 主导）

**适用场景**：品牌页面、作品集、概念验证、营销落地页

**创意权重**：90% | **规范权重**：10%

**执行方式**：
1. 直接调用 `frontend-design` skill
2. 让其自由发挥美学方向（brutally minimal, maximalist chaos, retro-futuristic 等）
3. 最后用 `ui-ux-pro-max` 检查关键可访问性问题（CRITICAL 级别）

**优点**：
- ✅ 独特、令人印象深刻
- ✅ 差异化强，避免通用 AI 美学
- ✅ 视觉冲击力强

**缺点**：
- ⚠️ 可能不符合某些行业标准
- ⚠️ 维护成本较高
- ⚠️ 需要更多设计解释

---

### 路线2：纯规范路线（ui-ux-pro-max 主导）

**适用场景**：企业后台、数据仪表板、表单密集页面、金融/医疗等严肃行业

**创意权重**：10% | **规范权重**：90%

**执行方式**：
1. 调用 `ui-ux-pro-max` 生成完整设计系统（`--design-system`）
2. 严格按照设计系统实现（57种规范、97种调色板、50+样式）
3. 使用 Pre-Delivery Checklist 验证所有规范

**优点**：
- ✅ 可靠、可维护
- ✅ 符合最佳实践
- ✅ 可访问性好（WCAG 2.1）
- ✅ 适合团队协作

**缺点**：
- ⚠️ 可能缺乏独特性
- ⚠️ 视觉冲击力较弱
- ⚠️ 容易与其他产品雷同

---

### 路线3：混合路线（规范基础 + 创意点缀）

**适用场景**：SaaS产品、电商平台、内容平台、需要平衡的大多数项目

**创意权重**：50-70% | **规范权重**：30-50%（动态调整）

**执行方式**：
1. 先调用 `ui-ux-pro-max` 生成设计系统（`--design-system`）
2. 将设计系统作为约束条件传递给 `frontend-design`
3. `frontend-design` 在规范框架内发挥创意
4. 最后用 `ui-ux-pro-max` 的 Pre-Delivery Checklist 验证

**优点**：
- ✅ 平衡独特性和可靠性
- ✅ 适用范围最广
- ✅ 既有创意又有保障
- ✅ 易于维护和扩展

**缺点**：
- ⚠️ 需要更多协调
- ⚠️ 可能需要迭代调整
- ⚠️ 执行时间较长

## 场景评分系统

系统会根据以下规则自动评分，推荐最合适的路线：

```
场景评分规则：
- 品牌页面/作品集/营销页 → 创意权重 +30
- 仪表板/后台/表单 → 规范权重 +30
- 电商/SaaS/内容平台 → 平衡（0）
- 金融/医疗/政府 → 规范权重 +20
- 艺术/设计/创意行业 → 创意权重 +20
- 用户明确要求"独特"/"创意" → 创意权重 +15
- 用户明确要求"规范"/"专业" → 规范权重 +15

最终推荐：
- 创意权重 > 规范权重 +20 → 推荐路线1
- 规范权重 > 创意权重 +20 → 推荐路线2
- 其他情况 → 推荐路线3（最常见）
```

### Step 1: 需求分析

从用户输入中提取：
- **项目类型**：SaaS, 电商, 作品集, 仪表板, 落地页, 博客, 移动应用等

- **行业特征**：金融, 医疗, 教育, 艺术, 游戏等
- **技术栈**：React, Vue, Svelte, HTML+Tailwind 等

### Step 2: 场景评分

```python
# 伪代码示例
creative_score = 0
standard_score = 0

# 项目类型评分
if "品牌页" in project_type or "作品集" in project_type:
    creative_score += 30
elif "仪表板" in project_type or "后台" in project_type:
    standard_score += 30

# 行业评分
if industry in ["金融", "医疗", "政府"]:
    standard_score += 20
elif industry in ["艺术", "设计", "创意"]:
    creative_score += 20

# 用户明确要求
if "独特" in keywords or "创意" in keywords:
    creative_score += 15
elif "规范" in keywords or "专业" in keywords:
    standard_score += 15

# 推荐路线
if creative_score > standard_score + 20:
    recommended_route = "路线1"
elif standard_score > creative_score + 20:
    recommended_route = "路线2"
else:
    recommended_route = "路线3"
```

## 故障排除

### 问题：生成的代码无法运行

**解决方案**：
1. 检查是否安装了所需的依赖（如 Tailwind CSS）
2. 确认技术栈版本是否兼容
3. 查看浏览器控制台的错误信息
4. 要求重新生成并明确指定技术栈版本

### 问题：设计风格不符合预期

**解决方案**：
1. 提供更详细的设计关键词（如："极简主义"而不是"简洁"）
2. 提供参考网站或设计风格示例
3. 明确指定要避免的设计元素
4. 尝试不同的路线或调整权重

### 问题：代码太复杂难以维护

**解决方案**：
1. 切换到路线2（纯规范路线）
2. 要求简化代码结构
3. 要求添加更多注释
4. 要求使用更常见的设计模式

### 问题：设计太保守缺乏创意

**解决方案**：
1. 切换到路线1（纯创意路线）
2. 提高创意权重到 70-80%
3. 明确要求"大胆的设计"、"独特的美学"
4. 提供创意方向的参考（如："brutalist"、"maximalist"）

## 总结

`design-orchestrator` 是一个智能编排系统，能够：

### 核心优势

✅ **智能分析**：自动识别项目类型、设计关键词、行业特征，推荐最合适的设计路线

✅ **灵活选择**：提供3条设计路线（纯创意、纯规范、混合），满足不同场景需求

✅ **动态平衡**：根据场景自动调整创意和规范的权重，适应不同项目需求

✅ **完整交付**：输出生产级代码 + 设计说明 + 决策日志 + 规范检查清单

✅ **强大协同**：调用 `frontend-design` 和 `ui-ux-pro-max` 两个子 skill，发挥各自优势

### 适用场景

| 场景类型 | 推荐路线 | 适用度 |
|---------|---------|--------|
| 品牌页面、作品集、营销页 | 路线1 (纯创意) | ⭐⭐⭐⭐⭐ |
| 企业后台、仪表板、表单 | 路线2 (纯规范) | ⭐⭐⭐⭐⭐ |
| SaaS、电商、内容平台 | 路线3 (混合) | ⭐⭐⭐⭐⭐ |
| 移动应用 | 路线2 或 路线3 | ⭐⭐⭐⭐ |
| 金融/医疗/政府项目 | 路线2 | ⭐⭐⭐⭐⭐ |

### 设计哲学

**路线1（纯创意）**：追求独特性和视觉冲击力，适合需要强烈品牌识别度的项目

**路线2（纯规范）**：追求可靠性和可维护性，适合需要符合行业标准的项目

**路线3（混合）**：平衡独特性和可靠性，适合大多数商业项目（推荐度 60%）

### 质量保证

所有路线都确保：
- ✅ 生产级代码质量
- ✅ 可访问性符合 WCAG 2.1 AA 标准
- ✅ 响应式设计（375px - 1440px）
- ✅ 性能优化（图片懒加载、CSS 动画优化）
- ✅ 完整的设计文档和决策日志
